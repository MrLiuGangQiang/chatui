# 23 思考内容展示设计

> 状态：已实现（2026-09-13）。本设计约束最终聊天中的思考过程、等待提示与请求理解轨迹的展示时机和视觉层级，不改变模型请求格式。

## 1. 范围与目标

- 思考过程必须与正式回答有明确、持续可见的视觉区分，不能只靠滚动后可能消失的标题或轻微文字色差。
- 思考完成后默认自动收起，保留内容并允许用户重新展开。
- 等待提示只表示“尚未收到任何上游有效输出”；收到第一条思考或正文增量后必须立即结束等待状态。
- 请求理解轨迹属于等待阶段；任何思考或正文增量到达后直接移除，不得继续显示“已等待 N 秒”或“已理解你的请求”。

## 2. 状态与流程

1. 请求已接受、尚未收到有效上游片段：显示“正在处理 已等待 N 秒”，允许请求理解轨迹原位展示。
2. 收到第一条非空思考或正文片段：停止等待计时，移除等待提示和请求理解轨迹。返回思考就显示思考，返回正文就显示正文。
3. 思考流持续期间：思考区保持展开，只使用简单的中性浅灰平面底色与正文区分，不增加背景模糊、阴影、边框、左侧色条或其他装饰；供应商返回的思考内容必须显示，不因本会话是否主动请求思考而丢弃。
4. 正式回答开始或思考流结束时：思考区标记为完成并默认收起；正式回答继续在原消息中输出。
5. 用户点击思考标题：允许重新展开，内容不丢失；刷新恢复时必须重新接续同一聊天任务，并还原已收到的思考内容，恢复更新不得重新写回等待提示。已完成思考仍默认收起。`outputStarted=true` 单独出现时也必须视为输出阶段已经到达：即使正文与思考缓冲区暂时为空，也不得重新显示或继续更新“已等待 N 秒”。pending display item 的历史恢复只能以 open renderer 回填当前首段，item 仍为 pending 时不得执行终态 `done`；后续 reasoning 增量必须继续追加，不能因节点 hydration 提前关闭 renderer。
6. 等待、思考、回答必须是互斥阶段；空 reasoning 更新不得创建或保留空的思考面板。所有流式回调必须按 `displayItemId` 解析当前 assistant 节点，不能依赖启动时捕获的旧节点。重新生成必须先原子清除旧 metrics、reasoning、pending feedback 和 intent trace，再进入路由阶段。

## 3. 展示契约

- 思考区继续使用 `.reasoning-panel.reasoning-live-panel`，使用中性浅灰平面底色；通过 `data-collapsed="0|1"` 和 `.reasoning-toggle[aria-expanded]` 表达展开状态。
- 完成态增加 `.reasoning-done`，收起仅隐藏 `.reasoning-content`，不得删除已经接收的思考文本。
- 请求理解轨迹使用 `.intent-reasoning-trace`；进入上游输出后直接从 assistant 消息中移除，不得继续占用正文或显示旧等待秒数。
- 等待提示、思考面板和正式回答共享同一 assistant 消息，但互不覆盖。
- 空 reasoning 不能产生“正在思考”面板；等待轨迹在第一条思考或正文到达后必须从实际渲染节点移除，即使节点在请求过程中被替换或重新挂载。
- 用户通过 wheel、touch、pointer 或 scrollbar 离开流式输出后，reasoning 和正文 token 都不能强制把视口拉回；只有用户点击“继续输出”、明确恢复跟随，或重新滚回底部后才恢复自动定位。
- 代码块异步高亮、代码展开/折叠和流式表格布局发生变化后，必须在布局完成后重新提交当前实时输出锚点；用户已进入手动滚动状态时则必须跳过，不能借异步布局回调抢回视口。普通回答、大文本增量渲染和 reasoning 必须转发浏览器流式渲染器的同一个 `onLayoutChange` 契约；代码展开/折叠由 Markdown 增强器统一上报，workflow 不得各自复制 DOM 监听或滚动补偿。
- 超过折叠阈值的长代码块在流式输出期间必须保持内部视口跟随最新一行；`enhanceCodeExpansion` 是折叠态末尾定位的唯一实现，DOM 重排、代码块移动和异步高亮不得把内部 `scrollTop` 重置到开头，新会话、重新生成和编辑重发共用同一规则。
- “跟随最新一行”只适用于活的渲染会话（流式增量、流式结束后的同一次渲染）。从历史重建的消息（刷新页面、切换会话、canonical 重渲染）传入 `reason: 'static'` 时，折叠代码块必须回到内容开头，否则长网页/长脚本会被误认为“只有后半截”。
- 刷新恢复时，只要存在可校验的 durable chat/image Job，旧的 pending-submit 记录不得阻止恢复；先清理该过期记录并继续连接原任务，只有没有任何服务端任务时才丢弃。

## 4. 安全与数据边界

本设计不新增网络请求、日志内容或凭据处理；为保证刷新、会话切换和后台恢复时等待轨迹不会复现，pending display item 增加 `outputStarted` 持久化标记，模型思考文本仍按现有隐私和持久化规则处理。

## 5. 验收标准

- 长思考流期间，等待提示在第一条思考片段到达后立即停止更新并消失。
- 思考区与正文在滚动后仍有清楚但克制的浅灰底色和文字颜色差异，同时保持平面。
- 思考完成后默认收起，点击后可重新展开且内容完整。
- 正文或思考开始后再次出现“已等待 N 秒”“已理解你的请求”均视为回归。

## 6. 回归测试

- `test/unit/chat-response-start-status.test.js`：验证首条思考增量停止等待计时、移除等待提示和请求理解轨迹，并验证未开启思考控制时仍显示供应商返回的思考内容。
- `test/unit/reasoning-panel-presentation.test.js`：验证思考区中性浅灰平面效果、完成默认收起、手动展开、请求理解轨迹在输出开始时消失，以及空 reasoning 不创建面板。
- `test/unit/chat-response-start-status.test.js`：验证首个正文片段清理实际渲染节点上的等待轨迹，而不是只清理过期节点引用。
- `test/unit/job-resume-contract.test.js`：验证刷新/切换会话后的 live resume 在已有 content、reasoning 或仅 `outputStarted=true` 时立即清除 pending 与 intent trace，不重放等待文案，并标记输出阶段。
- `test/unit/edit-resend-pending-position.test.js`：验证复用旧 assistant 节点重新生成时，旧 metrics、reasoning、pending feedback 和 intent trace 被原子清除。
- `test/unit/reasoning-refresh-resume.test.js`：验证思考流期间刷新可恢复仅有思考内容的 pending 项，绕过思考开关强制还原已收到的思考，并清除旧快照中残留的等待文案与 pending 标记。
- `test/unit/streaming-code-block.test.js`：验证代码展开/折叠、异步高亮和折叠态内部视口统一维持最新代码位置，并上报同一个外层布局变更回调。
- `test/unit/streaming-scroll-transaction.test.js`：验证普通、大文本和 reasoning 流式入口共享实时输出提交契约，手动滚动不会触发强制回拉。
- `test/unit/streaming-scroll-stability.test.js`：验证过期渲染器的迟到布局回调不能抢占新的实时输出或移动当前视口。
- `test/unit/markdown-streaming-canonical-final.test.js`：验证大文本增量渲染挂载后，折叠代码仍保留最新一行且最终 Markdown 与规范渲染一致。
