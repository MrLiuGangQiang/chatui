# 22 网页输出渲染隔离设计

> 状态：设计基线，已进入实现。
> 日期：2026-09-13
> 关联文档：`02-总体架构与模块边界.md`、`05-安全设计.md`、`06-工程规范与代码规范.md`、`07-测试与质量门禁.md`

## 1. 范围与目标

助手输出完整网页 HTML 时，聊天消息必须只展示轻量代码内容，完整页面只能在用户主动打开的 sandbox 预览中运行：

- 原始 `<!doctype html>` / `<html>` 文档不得作为实时 DOM 插入聊天消息；
- 流式输出中尚未闭合的网页文档也必须提前转义，不能等 `</html>` 到达后才保护主页面；
- Markdown 代码围栏中的网页源码保持原有代码块语义，不重复包装；
- 网页预览卡片继续从原始文本提取完整文档，预览和下载继续使用原始源码；
- 该规则同时适用于普通最终渲染、渐进式大输出渲染和流式 Markdown 预览。

问题基线：约 447 KB 的原始网页会在聊天消息中生成约 2.4 万个 DOM 节点，并占用约 450 ms 主线程；页面越复杂，流式更新、布局、滚动和持久化越容易卡死。网页源码应作为文本/代码处理，而不是作为应用主 DOM。

非目标：

- 不取消网页预览、交互脚本、下载或新窗口能力；
- 不把预览 iframe 改成服务端渲染或代理页面；
- 不降低现有 1.5 MB 预览源码上限；
- 不改变 Markdown、Mermaid、公式或普通内联 HTML 片段的既有语义。

## 2. 流程与状态

```text
助手原始输出
  -> 标记完整源码用于网页预览候选
  -> Markdown 渲染前扫描非代码围栏区域
      -> 遇到行首 <!doctype html> / <html> / 完整 <svg>
          -> 从该位置到当前输出末尾转义为等长安全代码围栏
      -> 代码围栏内部内容保持不变
  -> Markdown 引擎渲染轻量代码块
  -> 消息操作区追加网页预览卡片
  -> 用户点击预览
      -> sandbox iframe 使用原始完整源码
```

渲染状态：

```text
{
  rawAssistantText,       // 预览提取的唯一事实源，保持原文
  safeDisplayMarkdown,    // 仅用于聊天消息渲染，网页文档已转义
  webPreviewCandidates    // 从 rawAssistantText 提取，不从 safeDisplayMarkdown 复制
}
```

## 3. 数据与渲染契约

- `escapeWebDocumentsForMarkdown(rawText)` 是纯函数，输入输出均为字符串，不访问 DOM、网络或状态；
- 行首且非代码围栏内的 `<!doctype html>`、`<html>` 或原始 `<svg>` 文档转换为带语言标记的代码围栏；
- 文档尚未闭合时，从文档起点到当前文本末尾全部进入安全代码围栏；后续增量输出继续位于围栏内；
- 代码围栏长度必须大于源码中最长连续反引号，防止源码提前闭合 Markdown；
- 已存在的 Markdown 代码围栏原样保留，不能嵌套或二次转义；
- `extractWebPreviewCandidates(rawText)` 继续使用原始助手输出，确保预览和下载内容不变；
- 安全显示文本不持久化为新的模型输入；会话的 `rawText`/预览候选仍以原始文本为准。

## 4. 安全与性能边界

- 完整网页中的 `<style>`、布局、表单、SVG 节点和大型表格不得进入消息主 DOM；
- `<script>` 只允许在用户主动打开、带 sandbox 的预览 iframe 中运行；
- 聊天消息 DOM 只增加一个代码块和少量预览卡片节点，节点数不再随网页内部结构增长；
- 显式语言代码块超过 12,000 字符、自动识别代码块超过 6,000 字符时跳过 highlight.js，只输出转义纯文本，避免高亮 span 数量失控；
- 转义为线性扫描，禁止对整段超长源码执行无界嵌套量词或 DOM 解析；
- 超过 1.5 MB 的文档不生成预览候选，但仍可按普通文本安全显示。

## 5. 验收标准

1. 原始完整 HTML 网页在聊天消息中显示为代码块，不生成页面内部 DOM；
2. 未闭合的流式 HTML 从起始标记开始即进入代码围栏；
3. Markdown `html`/`svg` 代码围栏保持原样；
4. 网页预览卡片数量、标题、预览源码和下载内容与原始输出一致；
5. 普通 Markdown 与内联 HTML 片段渲染不回归；
6. 大型网页输出不会在主消息中产生与页面内部节点数同量级的 DOM；
7. `npm run check` 项目、架构、语法和全量测试通过。

## 6. 回归测试

- `test/unit/web-preview.test.js`：完整和未闭合网页转义、代码围栏保护、源代码预览提取、原始源码保留；
- `test/unit/markdown-linebreaks.test.js`：确认浏览器 Markdown 引擎在渲染前调用安全网页转义；
- `npm run check`：全量质量门禁。

## 7. 演进边界

若后续需要显示网页源码高亮、折叠源码或“仅预览不显示源码”，应在网页预览模块中显式设计视图状态，不能重新把完整网页 DOM 注入聊天消息。
