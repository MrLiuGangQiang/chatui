# 03 数据模型与持久化设计

> 浏览器侧本地持久化是核心；PostgreSQL 只承担可选的使用统计，未配置时显式不可用。

## 1. 存储分层

| 存储 | 用途 | 边界 |
| --- | --- | --- |
| `localStorage` | 配置、会话元数据、消息文本、任务恢复、UI 状态 | 不放大体积二进制 |
| `IndexedDB`（`openapi-chat-image-db-v1`） | 生成图片与附件二进制缓存 | 只存可重取/可备份的媒体 |
| PostgreSQL（可选） | 使用统计与排行榜 | 数据库未配置时统计显式不可用，不影响聊天/图片/静态页 |

## 2. localStorage key（`client/config/storage-keys.js` 为准）

| key | 内容 |
| --- | --- |
| `openapi-chat-image-config-v2` | Endpoint、API Key、模型与图片参数配置 |
| `openapi-chat-image-chat-v1` | 历史会话数据 |
| `openapi-chat-image-ui-v1` | UI 偏好 |
| `openapi-chat-image-sessions-v1` | 会话列表 |
| `openapi-chat-image-active-session-v1` | 当前会话 id |
| `openapi-chat-image-last-image-v1` | 最近生成图片 |
| `openapi-chat-reasoning-persist-v1` / `-mode-v1` / `-type-v1` | 思考内容与思考强度持久化 |
| `openapi-chat-image-session-sidebar-collapsed-v1` | 会话栏折叠 |
| `openapi-chat-image-job-v1` / `-chat-job-v1` / `-batch-v1` | 图片/聊天/批量任务恢复 |
| `openapi-chat-image-db-v1` | IndexedDB 库名 |

## 3. 会话与消息模型

会话对象（`client/app/state.js`）至少包含：`id`、`title`、`customTitle`、`messages`、`display`、`systemPrompt`、`imageStylePrompt`、`chatModel`、`promptDraft`、`reasoningMode/Type`、时间戳与 `busy`。消息以稳定的 turn/message 身份存储，导入与恢复用墓碑标记删除项，避免重复或丢失。

## 4. 任务与恢复

- job kind：`chat` / `image` / `image-batch`；服务端为权威运行时，浏览器侧保存恢复元数据。
- 未完成提交（pending）在刷新后按会话重建；任务预算、幂等键与终止态由服务端校验。
- 图片批量使用 `image_task_lineage.v1` 为每个子任务单独保存 lineage，不把批次末项伪装成整个批次的前序。

## 5. 版本化契约（协议单源）

| 契约 | 用途 |
| --- | --- |
| `intent_understanding.v1` | 理解节点输出 |
| `route_intent.v3` | 路由六字段协议（旧 v1/v2 只允许显式迁移适配） |
| `dispatch_contract.v1` | 唯一执行授权 |
| `task_continuity.v1` | 图片文字任务 replace/amend 连续性 |
| `image_task_lineage.v1` | 批量子任务 lineage |
| `image_plan.v1` / `multi_task_plan.v1` | 图片计划与多任务计划 |
| `resource_catalog.v1` | 历史资源目录 |
| `route_model_attempt_ledger.v1` | 模型调用预算账本 |
| `client_execution_trace.v1` | 客户端执行被拒绝事件 |

## 6. 变更纪律

- 浏览器存储结构变更必须向后兼容：读取旧结构、显式迁移、导入重置墓碑，禁止静默丢弃。
- 协议字段变更必须升版本并保留旧版本迁移路径，禁止运行时静默补默认值。
- 删除或移动 key 前先核查测试、备份/导入与任务恢复消费者。
