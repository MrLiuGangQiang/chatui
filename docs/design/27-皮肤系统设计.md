# 27 皮肤系统设计

> 状态：已实现（2026-09-15）。本设计定义 ChatUI 皮肤系统的数据模型、CSS 装配、运行时切换、持久化、切换入口与回归门禁。默认皮肤沿用原浅色令牌；自 2026-09-15 起其画布改为用户确认的丝绢波浪背景，当前会话使用更突出的强调选择态（见 5.1）。 **加载机制更新（2026-09-16）**：本文第 3 节的 CSS 装配顺序与「皮肤后覆盖层白名单」已被 29 号设计取代——非默认皮肤不再进入 bundle，改由 boot 按需注入单条样式表；白名单机制由 head 结构取代。皮肤目录、注册表、持久化与切换交互契约不变。

## 1. 范围与目标

- 把当前界面抽取为**默认皮肤**，并新增**古韵**与**雪山**皮肤；切换按钮固定在视口右下角。
- 皮肤切换即时生效、跨刷新持久化，且首屏渲染前应用，避免闪烁。
- 不改聊天、图片、任务、路由等业务逻辑；皮肤只承载颜色、材质、阴影、边框和少量装饰，不改变布局、尺寸、显隐、焦点或交互契约。

## 2. 数据与状态模型

| 字段 | 约定 |
| --- | --- |
| 皮肤 id | `default`、`ink`、`snow`；未知或损坏值一律回退 `default`（失败关闭） |
| 激活标记 | `<html data-skin="<id>">`，CSS 只通过该属性作用域选择器 |
| 持久化 | `localStorage` key `openapi-chat-image-skin-v1`，注册于 `client/config/storage-keys.js` |
| 皮肤注册表 | `client/core/skin.js` 的唯一 `SKINS` 数组（id、label、description） |
| 皮肤源码目录 | 每套皮肤一个独立目录 `styles/skins/<id>/skin.css`；该皮肤引用的图片等资源与 CSS 同目录存放。默认皮肤登记在 `index.html` 清单内随 bundle 加载；其余皮肤**不登记清单**，由 boot 脚本按需注入（见 29 §6）。共享切换器外壳固定在 `styles/skin-system.css`，不属于任何单套皮肤 |
| 首屏防闪烁 | `index.html` head 内联脚本在 body 前读取并设置 `data-skin`；该处只做白名单校验，业务目录仍以 core 为事实源 |

## 3. CSS 装配与“默认皮肤抽取”

装配顺序与优先序（自 2026-09-16 起由 29 号设计定义，此处保留摘要）：

> 评审后功能覆盖（post-skin 静态 head 链接）> 激活皮肤（boot 注入链接）> `skins/default`（bundle 内）> surfaces 视觉域 > 主题与基座。

bundle 内的 CSS 清单顺序（沿用无构建 manifest）：


1. 既有 `styles.css`、feature 样式、`flat-theme.css`、`calm-theme.css`：默认皮肤的完整结构样式与组件规则，保持不变；
2. `styles/skins/default/skin.css`：从默认皮肤**抽取出的权威设计令牌** `--skin-*`，并把既有变量（`--bg/--surface/--text/--muted/--border/--accent/--ds-*/--chatui-*` 等）统一别名到 `--skin-*`；末尾的 scenic canvas 层把画布换成自带 `styles/skins/default/scenery.jpg`（丝绢波浪照片）+ 浅白罩纱，并让 `.main/.messages` 透明以露出画布；
3. `styles/skin-system.css`：右下角切换按钮与菜单的共享外壳，只依赖 `--skin-*`/既有变量；
以下两套皮肤**不在 bundle 内**，仅在激活时由 boot 注入自己的单条样式表（29 §6）：

4. `styles/skins/ink/skin.css`：古韵皮肤。`html[data-skin="ink"]` 覆盖 `--skin-*`，并内置一份**生成式颜色重映射快照**：扫描默认皮肤全部 8 个样式文件中的硬编码 `color/background/border` 声明，按中性墨色、语义色和表面层级映射为墨色文字、青灰宣纸表面与青黛语义色。`styles/skins/ink/scenery.jpg` 是已确认的山水背景资产；最终调色层把主色统一为雾纸白、青灰绿与墨色，仅保留少量朱砂点缀。消息气泡、输入卡、对话框、公告、统计卡与欢迎卡统一使用 `--ink-paper / --ink-paper-raised` 同一纸绢材质和同一发丝边框，避免组件像独立白色图层贴在背景上。生成图容器保持无父级卡片；用户消息使用半透明纸条；图片操作、消息操作与意图轨迹使用同一细边框/纸绢玻璃细节，避免大块浮层。
5. `styles/skins/snow/skin.css`：雪山皮肤。`html[data-skin="snow"]` 覆盖 `--skin-*`；以自带 `styles/skins/snow/scenery.jpg`（雪峰湖泊照片）为画布，叠加白色霜雾罩层；导航与浮动控件使用霜白玻璃（半透明白 + `blur(12px)`），主色为冰川蓝 `#2f7fc4`；用户消息为冰川蓝纸条，助手消息为霜白卡片，选中会话使用蓝调底色 + 加粗标题（不带左侧色条）。公告中心、反馈弹窗与用量统计自带默认配色（靛蓝公告、饱和蓝统计与紫/琥珀/玫红分档），在雪山皮肤下必须整体改写到同一霜化玻璃家族：遮罩、hero、表面、页脚、chip、引用块、按钮、页签、排行、指标分档与反馈控件一律经 `html[data-skin="snow"]` 重新映射到 `--skin-*` 令牌与霜化材质；统计分档收敛为单一冷色渐变（冰川蓝、青灰、暖沙、灰玫红），徽章名次奖牌降低饱和但保留语义。通用 `--snow-*` 组内规则（如 `--snow-surface`）必须与具体组件族规则分层清晰，且任何同特异性的通用兜底规则（如 `.usage-token-badge`）必须排在其分档族（`.usage-token-badge-N`）之前，否则级联会抹掉分档色。
- 覆盖层顺序：`styles/message-actions-text.css` 不再是 manifest 条目，而是 head 中带 `data-chatui-post-skin="1"` 的静态链接，解析位置在 boot 脚本之后，因此任何注入的皮肤样式表都不可能越过它；原先靠 `POST_SKIN_CSS_ALLOWLIST` 测试白名单维持的约定，现在由加载机制本身保证（29 §8）。

- 默认皮肤无 `data-skin` 特例选择器，因此现有像素级外观不变；ink 皮肤不会污染默认皮肤。
- 新增 CSS 均在 `Dockerfile COPY styles ./styles` 与 `server/build-identity.js` 的既有扫描范围内，无需改部署流程。

## 4. 运行时切换

- 模块分层：
  - `client/core/skin.js`：纯逻辑（校验、读取、写入、目录），注册 `skinCore`；
  - `client/features/skin-system/skin-switcher.js`：创建右下角浮层按钮与菜单、绑定事件、同步 `data-skin` 与存储，注册 appContext 模块 `skinSystem`；
  - `client/app/bootstrap-workflow.js`：启动时调用 `skinSystem.init({document, storage})`。
- 交互：点击按钮展开菜单；选项为 `role="menuitemradio"`；选择后立即设置 `data-skin`、写 localStorage、更新选中态并收起；点击外部或 `Escape` 收起。
- 图标：切换按钮固定展示**彩色调色盘**（木色盘身 + 五个彩色颜料点，内联 SVG、`aria-hidden`）；图标颜色烘焙在 SVG 内，CSS 不得用 `currentColor`/`fill: none` 覆盖，悬停与展开态只改变按钮底色、描边和阴影。
- 可访问性：按钮带 `aria-haspopup/aria-expanded/aria-controls`，菜单带 `role="menu"`，键盘焦点可见；文本一律用 `textContent` 写入，杜绝 HTML 注入。

## 5. 皮肤视觉契约

### 5.1 默认（default）

- 画布：`styles/skins/default/scenery.jpg`（丝绢波浪照片）铺满视口，叠加 `rgba(247,248,251,.58-.74)` 浅白罩纱；色板令牌与组件配色保持原有浅色体系；
- 会话栏：选中项在玻璃侧栏上使用约 18% 蓝色强调底、可见蓝色发丝边框、深蓝加粗标题和强调色计数；悬停时进一步加深，但不使用左侧色条；
- 表面：`.main/.messages` 透明露出画布；侧边栏与图标栏为高透明白玻璃（`rgba(255,255,255,.20)`，约 80% 透明 + `blur(12px)`，不带色条）；欢迎页 hero、功能卡等原有白色卡片保持不变，作为画布上的白色表面；
- 背景资源与 CSS 同目录（`styles/skins/default/`），bundle 重写为 `/styles/skins/default/scenery.jpg`。

### 5.2 古韵（ink）

- 画布：已确认的青灰绿山水画背景，中央叠加雾纸柔光；整体色相为宣纸白、雾绿、青灰与墨色；
- 表面：导航使用半透明宣纸玻璃（`--ink-chrome` 罩层 + `rgba(247,242,233,.46)` 纸色 + `blur(10px)`），山水背景可透出；主要工作表面统一使用 `--ink-paper-raised`，次级卡片统一使用 `--ink-paper`；主按钮使用连续青黛墨绿渐变，白色文字保证对比度；朱砂只用于小印点和必要警示。
- 文本：全量硬编码文字色均重映射为浅蓝白正文、蓝灰次级文本与高亮语义色（蓝/紫/绿/红/橙/青），链接、活动态与焦点为青色系；
- 消息：用户与助手气泡均为完全透明表面（无填充、无边框、无阴影、无 backdrop-filter），正文直接落在山水背景上；头像使用青色/品红渐变；
- 会话栏：选中项使用青黛色底（墨绿约 34% 透明度，不带左侧色条）+ 加粗标题 + 强调色计数，悬停态明显轻于选中态，保证一眼分辨当前会话；
- 预览层：全屏图片预览使用暗色墨壳；预览操作图标跟随暖纸色（下载图标不得沿用生成式重映射留下的 `#52606d` 灰，以免看起来像禁用态），悬停时提亮；
- 思考区：保持中性深色平面，不添加阴影、模糊、边框或色条装饰（继承 23 的精神）；
- 动效：遵守 `prefers-reduced-motion`；皮肤切换本身不播放常驻动画。

### 5.3 雪山（snow）

- 画布：`styles/skins/snow/scenery.jpg`（雪峰、冰川湖与草甸照片）铺满视口，叠加 `rgba(255,255,255,.50-.64)` 霜雾罩层，正文落在浅色区域保证可读性；
- 表面：导航与图标栏使用半透明霜白玻璃（`rgba(255,255,255,.46)` + `blur(12px)`），山水…雪山照片可透出；主要工作表面（输入框、对话框、统计卡）保持霜白卡片（白色 94% + 蓝色发丝边框 + 冷色投影）；
- 主色：冰川蓝 `--skin-accent: #2f7fc4`，语义色改为雪线红 `#c0504a`、松绿 `#3d8a67`、暖赭 `#bd873c`；
- 消息：用户与助手气泡均为完全透明表面（无填充、无边框、无阴影、无 backdrop-filter），正文加白色柔光投影保证雪地上的可读性；思考面板保留轻霜底；
- 会话栏：选中项使用蓝色底纹 + 加粗标题 + 强调色计数，不带左侧色条；
- 动效：遵守 `prefers-reduced-motion`；皮肤切换本身不播放常驻动画。

## 6. 验收标准

1. 首屏无闪烁：head 内联脚本设置 `data-skin`；未知值回退 `default`。
2. 默认皮肤令牌与整体配色不变，当前会话必须是高辨识度强调选择态；画布必须是自带的丝绢波浪背景（`testDefaultSkinShipsTheSilkWaveCanvas` 校验资产、引用与 bundle 重写），聊天主区保持透明。
3. 古韵皮肤在 `html[data-skin="ink"]` 下覆盖画布、导航、消息、输入区、对话框与统计面板等主要表面，并对默认皮肤 8 个样式文件中的硬编码文字/背景/边框颜色进行全量重映射，保证可读性。消息气泡保持完全透明，左侧会话栏与图标栏保持半透明玻璃，山水背景可透出。
4. 右下角按钮固定展示彩色调色盘图标，可展开两套皮肤，选择后即时生效并持久化；刷新后保持。
5. 雪山皮肤在 `html[data-skin="snow"]` 下以自带 `styles/skins/snow/scenery.jpg` 为画布（bundle 重写为 `/styles/skins/snow/scenery.jpg`），霜白玻璃与冰川蓝主色贴合背景；切换菜单可选中并持久化。
6. `npm run check` 全绿；新增回归测试接入 runner 与 CI。
