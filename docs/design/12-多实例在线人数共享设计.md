# 12 多实例在线人数共享设计

## 1. 范围与原则

- 目标：在多个 ChatUI 副本部署时，`/api/presence` 返回全局在线人数，任一实例的 join/leave/heartbeat 都能被正确计入。
- 不做：不改变浏览器 presence 协议，不引入用户身份去重，不把 Redis 当成任务/会话存储。
- 失败语义：Redis 不可达时 presence 端点返回 `503 {available:false}`，核心聊天/生图/附件不受影响；未配置 `REDIS_URL` 时保持原单实例内存行为。

## 2. 流程/状态机

- `server/services/presence.service.js`：单实例内存 `Map<clientId, {res, lastSeen}>`，保留为默认实现。
- `server/services/presence.redis.js`：当配置 `REDIS_URL` 时启用。
  - 全局在线表为 Redis 有序集合 `chatui:presence:clients`，score = lastSeen。
  - 每个进程本地仍保存 `Map<clientId, {res}>`，只用于向本机 SSE 连接写数据。
  - join = 本地写入 + `ZADD`；leave = 本地删除 + `ZREM`；touch = `ZADD` 刷新 score；sweep = `ZREMRANGEBYSCORE` 清理过期，并结束本机已不存在的 clientId 连接。
  - 计数变化通过 Redis pub/sub 频道 `chatui:presence:events` 广播到所有实例。

## 3. 契约与数据模型

- Redis key：`chatui:presence:clients`（ZSET，member=clientId，score=lastSeen ms）。
- Redis channel：`chatui:presence:events`，消息体 `{count, timestamp}`。
- 浏览器/服务端 HTTP 契约不变：
  - `GET /api/presence` -> `{count, timestamp}`
  - `GET /api/presence/stream?clientId=...` -> SSE presence 事件
  - `POST /api/presence/heartbeat` body `{clientId}` -> `{ok:true}`

## 4. API 与缓存语义

- presence 端点始终 `Cache-Control: no-store`。
- Redis 连接使用 `REDIS_URL`；密码只存在于服务端环境变量，不进入 `/api/config/public`、静态资源或日志。

## 5. 安全与可观测性

- `REDIS_URL` 不得出现在任何公开配置或静态目录。
- Redis 连接错误记录到 `errorLog`，来源标记 `presence-redis` / `presence-redis-subscribe`。
- 日志遵守既有脱敏规则，不记录 Redis URL 或密码。

## 6. 验收标准与回归测试

- 未配置 `REDIS_URL` 时，原 presence 行为与测试全部通过。
- 配置 `REDIS_URL` 时：
  - 两个不同 clientId join 后全局计数为 2。
  - 同一 clientId 重连不重复计数。
  - 心跳可在任意实例刷新共享 score。
  - sweeper 只清理过期全局槽位，并结束对应本机 SSE。
  - pub/sub 收到的 count 变化会写回所有本机 SSE 订阅者。
  - 路由对异步 snapshot/join/touch/leave 正确 await。
- 回归测试：
  - `test/unit/presence-redis.service.test.js`
  - `test/unit/presence-routes-async.test.js`
  - 既有 `test/unit/presence.service.test.js`、`test/unit/presence-routes.test.js`、`test/unit/presence-ui.test.js` 保持通过。
