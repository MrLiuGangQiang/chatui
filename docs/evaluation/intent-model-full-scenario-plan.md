# 意图识别模型全量场景评估方案

> 状态：方案草稿，待执行
> 日期：2026-09-02
> 范围：三个意图识别模型 × 全产品场景 × 难度梯度

## 1. 目标

不局限现有回归用例，按产品功能与代码逻辑梳理完整意图路由场景，用三个意图识别模型全量实测。对失败场景先定位根因、给出明确修复方案，并至少交叉验证三次后再修改代码；不允许兜底式修改，必须从路由逻辑根源修复，不能靠堆提示词掩盖问题。修改后复测并输出报告。

## 3. 场景总览

路由协议覆盖以下 operation：

1. `plain_chat`：纯文本对话
2. `file_qa`：文件问答
3. `multimodal_qa`：图文混合问答
4. `image_qa`：图片理解问答
5. `image_compare`：多图比较
6. `ocr`：文字识别
7. `text_to_image`：文生图
8. `image_reference_gen`：参考图生成
9. `edit_image`：图片编辑
10. `web_search`：联网搜索

交叉维度：

- `relation`：`new` / `followup` / `continuation`
- `task_shape`：`single` / `multi`
- `goal_mode`：`replace` / `amend`
- 资源绑定：`current` / `quoted` / `history` / `context`，类型 `image` / `file` / `message` / `text`
- 澄清：是否要求澄清、unresolved 原因
- 干扰项：历史图片/文件/文本、引用消息、执行记录、视觉交付记录、多任务计划

## 4. 难度梯度定义

- **L1 简单**：单一明确操作，无历史干扰，无否定/排除，无多资源选择。
- **L2 复杂**：一个操作但含多个约束/属性/资源引用，语义明确。
- **L3 困难**：有历史图片/文件/执行记录/引用消息等干扰，需正确边界判断；或含否定、排除、数字选择、回指。
- **L4 超级困难**：多轮跨任务延续、证据优先级、几乎可混淆的跨操作边界、多资源+多任务+修订组合、视觉交付与文本话题穿插。

## 6. 执行与验证门禁

1. 先冻结场景文档与 fixture，不改业务代码。
2. 三个模型分别全量执行，输出 JSON 报告到 `temp/reports/`。
3. 汇总每个模型的：
   - 平均分、perfect case 率
   - 分维度准确率
   - 分场景组得分
   - safety-critical 失败清单
4. 对每个失败：
   - 复现至少三次确认非随机
   - 定位是模型能力、路由 schema、prompt 契约、还是本地归一化/编译逻辑
5. 修改方案必须先通过三次交叉验证（同一 fixture 连续三次，或三个模型各一次基线一致）再落地。
6. 不允许仅靠给 prompt 堆规则；逻辑层修复优先。
7. 修复后三模型复测，输出最终报告。
