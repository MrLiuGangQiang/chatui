# 手工回归测试用例

本文覆盖以下问题：图片生成消息位置、多标签页消息丢失、澄清续答提示，以及图片尺寸接口错误。

## 测试前准备

启动本地服务：

```powershell
npm.cmd start
```

浏览器打开 `http://localhost:3000`，按 `Ctrl + Shift + R` 强制刷新。配置可用的聊天与生图模型，并新建一个“回归测试”会话。

先发送：

```text
请回复：测试环境已就绪
```

预期：正常出现助手回复。

## 1. 图片生成后消息位置

### 1.1 单张图

输入：

```text
生成一张 1024x1024 的蓝天白云、远处雪山、前景湖泊的风景图
```

操作：发送后不刷新，等待图片出现，再等待约 5 秒。

通过标准：

- 图片所在消息完整可见，未被底部输入框遮挡。
- 图片从加载中变为真实图片时，最多发生一次平滑位置调整，不跳到顶部或旧消息。
- 未主动滚动时，滚动条保持在结果附近。
- 刷新后图片与位置仍正常。

### 1.2 多张图与手动滚动

输入：

```text
生成 4 张不同构图的橙色小猫插画
```

操作：发送后，在图片加载期间向上滚动一点，等待全部图片加载完成。

通过标准：

- 图片网格正常，无覆盖。
- 用户主动向上滚动后，页面不强行拉回底部。
- 未主动滚动时，完成加载后仍停留在结果附近。

## 2. 两个标签页切换后消息不丢失

两个标签页必须使用同一个浏览器、同一个地址和同一个会话。

### 2.1 基础切换

1. 创建“多窗口测试”会话。
2. 复制当前页面地址，在第二个标签页打开。
3. 在两个标签页都进入“多窗口测试”。
4. 在标签 A 发送：

```text
多窗口测试消息 A1：请原样回复 A1
```

5. 用户消息刚出现时立即切换到标签 B，停留 2 至 5 秒，再切回 A。
6. 等待回复完成，在 A 刷新页面。

通过标准：用户消息和助手回复在 A 中存在；刷新后仍存在；B 刷新后也能看到相同历史。

### 2.2 高频切换

在标签 A 逐条发送下列内容；每条发送后立刻切到 B，再切回 A：

```text
多窗口测试消息 A2：第一条
```

```text
多窗口测试消息 A3：第二条
```

```text
多窗口测试消息 A4：第三条
```

等待完成后分别刷新 A 和 B。

通过标准：A2、A3、A4 及其回复均存在且顺序一致，无重复、无丢失。

### 2.3 旧标签覆盖

1. 打开 A、B 并进入同一会话，保持 B 为旧页面，不刷新。
2. 在 A 发送：

```text
多窗口测试消息 A5：旧标签不能覆盖这条消息
```

3. 立即切到 B，什么都不做，等待 3 秒后回到 A。
4. 在 A 刷新；再关闭并重新打开该会话。

通过标准：A5 及回复始终存在。

## 3. 澄清续答

### 3.1 图片选择澄清

先依次生成：

```text
生成一张红色小猫插画
```

```text
生成一张蓝色小狗插画
```

完成后输入：

```text
把它改成水彩风
```

若系统要求选择图片，回答：

```text
第二张
```

通过标准：不出现“暂时无法确认这条回复是否在回答上一个澄清问题”；系统继续原任务或提出新的有效缺失信息。

### 3.2 补充条件澄清

输入：

```text
生成一张海报
```

若系统追问，回答：

```text
科技感蓝紫配色，主题是人工智能，竖版 1024x1536
```

通过标准：系统继续生成或提出明确的新缺失条件，不丢失“生成一张海报”这个原任务。

### 3.3 独立新任务

在仍有未完成澄清时输入：

```text
解释一下 JavaScript 的 Promise 是什么
```

通过标准：不应被作为图片选择或图片生成条件处理。

## 4. imageSrcSize 错误

1. 打开浏览器开发者工具的 Console。
2. 强制刷新页面。
3. 上传一张本地 PNG/JPG，或作为消息附件发送。
4. 再执行一次图片生成。

通过标准：Console 不出现：

```text
getMediaWorkflow(...).imageSrcSize is not a function
```
