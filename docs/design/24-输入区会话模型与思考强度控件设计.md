# 24 输入区会话模型与思考强度控件设计

> 状态：已实现（2026-09-14）。本设计调整输入区呈现与交互，并固定“不思考”必须显式关闭上游 reasoning；模型选择和思考强度持久化规则不变。

## 1. 范围与目标

- 在聊天输入区右侧、发送按钮旁放置一个整体化的运行设置开关，避免用户必须在输入区左侧逐个辨识无文字图标。
- 开关由两个相邻分段组成：会话模型与思考强度。两段共享同一视觉容器，但分别打开各自菜单。
- 模型分段始终显示当前会话实际会使用的聊天模型：有会话覆盖时显示覆盖模型，否则显示全局聊天模型。
- 思考强度分段始终显示当前会话下一轮请求的设置：`不思考`、`低`、`中`、`高`、`超高` 或 `最高`。
- 附件、会话提示词和生图样式入口保留在输入区左侧，不改变其职责。

## 2. 状态与流程

1. 会话模型的有效值继续由 `getSessionChatModel` 计算：会话模型在已加载模型列表内时使用会话覆盖，否则回退到全局聊天模型。
2. 思考设置继续使用会话已有的 `reasoningMode` 与 `reasoningType`；`none` 表示关闭，其余值为 `low`、`medium`、`high`、`xhigh`、`max`。用户选择关闭时，请求必须显式发送 `reasoning: { effort: "none" }`；不能通过省略字段依赖供应商默认值。Qwen 系列同时发送 `enable_thinking: false`，GLM/DeepSeek/Kimi 系列同时发送 `thinking: { type: "disabled" }`，避免兼容网关忽略 OpenAI reasoning 字段后继续默认思考。
3. 用户点击模型分段时打开会话模型菜单；选择后更新当前会话并立即刷新显示值。
4. 用户点击思考分段时打开强度菜单；菜单包含“不思考”和全部有效强度。选择后更新当前会话并立即刷新显示值。
5. 会话切换、新会话创建和全局聊天模型变更时，模型显示值必须重新计算；会话切换时思考显示值也必须同步到该会话设置。
6. 输出进行中继续禁止修改模型和思考设置；锁定状态必须同时对按钮和菜单项生效。
7. 设置只影响后续请求；已完成消息的思考内容和历史记录不因开关变化而被删除。

## 3. 展示与契约

- 右侧容器使用 `.composer-action-right`，整体开关使用 `.composer-runtime-switch`，并置于 `#sendBtn` 旁。
- 保留 `#sessionModelBtn`、`#sessionModelPanel`、`#reasoningMenuBtn`、`#reasoningMenu` 作为现有交互挂载点；新增 `#sessionModelLabel` 与 `#reasoningTypeLabel` 作为当前值文本。
- `#reasoningMenu` 必须提供 `data-reasoning-type="none"`，并与现有强度项使用相同的单选状态。
- 两个分段按钮必须提供可理解的 `title` 与 `aria-label`；展开状态继续通过 `aria-expanded` 和 `aria-hidden` 表达。
- 窄屏下保留两个分段的当前值，优先截断模型名而不是隐藏思考强度；菜单必须限制宽度并可纵向滚动。
- 在 420px 及以下，工具入口与“模型/思考 + 发送”分两行排列，避免任一入口或发送按钮被挤出视口。
- 不新增 API、localStorage 字段、会话字段或日志内容。

## 4. 安全与数据边界

本设计只消费已持久化的会话设置并在浏览器中渲染，不新增网络请求、凭据处理或服务端数据。模型值必须作为文本写入 DOM，禁止拼接为未转义 HTML。

## 5. 验收标准

- 用户无需打开菜单即可看到当前会话的有效模型与思考强度。
- 模型和思考开关在发送按钮旁形成一个连续的整体，不遮挡输入框和左侧工具入口。
- 选择“不思考”后显示为“不思考”，下一轮请求显式发送 `reasoning: { effort: "none" }`；再次选择强度后发送对应 effort 与 summary。
- 切换会话后，模型和思考显示值与新会话实际使用的设置一致。
- 输出过程中开关和菜单不可修改，结束后恢复。

## 6. 回归测试

- `test/unit/composer-runtime-controls.test.js`：验证右侧一体化控件结构、模型显示值、思考显示值和“不思考”选项。
- `test/unit/intent-reasoning-disabled.test.js` 与 `test/unit/chat-file-inputs.test.js`：验证用户关闭思考时 payload 明确包含 `reasoning.effort=none`，过期强度参数不能覆盖关闭值。
- 扩展 `test/unit/reasoning-workflow.test.js`：验证思考强度显示映射与锁定状态。
- 扩展会话切换相关测试或新增断言：验证新会话/会话切换后显示值重新同步。
