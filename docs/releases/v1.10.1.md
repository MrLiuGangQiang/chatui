# ChatUI v1.10.1

本版本重新设计了应用内更新日志的阅读界面，重点改善版本较多、单篇日志较长、包含宽表格或代码块时的可读性，并修复移动端日志弹窗被右下角悬浮按钮遮挡的问题。

本次仅调整更新日志界面与渲染性能，不改变 `v1.10.0` 已发布的原生文件输入能力，也没有缩减任何已支持的文件格式。

## 更新日志界面

### 更清晰的版本结构

- 更新日志改为独立的版本卡片，版本号、版本标题和正文层级更加明确。
- 最新版本默认展开并显示“最新版本”标记；历史版本默认折叠，可按需逐条查看。
- 自动识别并去除重复标题，不再出现 `v1.10.0 ChatUI v1.10.0` 一类重复版本文案。
- 重新设计弹窗标题区、关闭按钮、版本折叠箭头、正文留白和滚动区域。

### 更顺畅的历史记录加载

- 首次只挂载最新 12 个版本，减少日志较多时的初始 DOM 数量。
- 点击“查看更早版本”后每次继续加载 12 个版本，并显示尚未加载的版本数量。
- 历史版本只有在用户展开时才渲染 Markdown；最新版本仍会在打开弹窗后立即展示。
- 已经展开并渲染过的版本会复用现有内容，避免反复执行 Markdown 渲染。

### Markdown 阅读体验

- 调整一级至四级标题、段落、列表、引用、链接、行内代码和代码块的字号、间距与颜色。
- 表格使用独立的横向滚动容器；宽表格只在卡片内部滚动，不再撑宽弹窗或整个页面。
- 代码块支持自身横向滚动和长内容换行，行内代码在窄屏下也可以安全断行。
- 保留共享 Markdown 渲染器和现有安全净化链路，没有引入第二套日志解析实现。

### 桌面端与移动端适配

- 桌面端采用更宽的阅读区域、固定标题区和独立正文滚动区，长日志不会超出视口。
- 640px 及以下视口使用底部弹层布局，并针对标题、卡片、正文、代码块和表格缩小间距。
- 移动端保留底部安全区，日志正文和宽表格不会造成页面级横向溢出。
- 调整日志弹窗层级，使其高于常驻悬浮入口，同时仍低于路由图主弹窗，避免控件穿透或遮挡。

## 当前支持的文件格式

以下能力与 `v1.10.0` 保持一致。非图片附件作为原始文件通过 Responses API 的 `input_file.file_data` 发送，不会在浏览器或 ChatUI 服务端本地解析正文；文件最终能否被读取，仍取决于上游 Endpoint 和所选模型是否支持对应文件类型。

### 图片附件

- 扩展名：`.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`、`.bmp`、`.svg`。
- 带有 `image/*` MIME 类型的文件也会进入图片附件链路。
- JPEG、PNG、WebP 会尽量压缩；BMP 会在浏览器支持时转换为 PNG。
- 图片继续使用多模态 `input_image` 或图片编辑链路，不会作为普通文档 `input_file` 发送。

### PDF、表格、文档和演示文稿

| 类别 | 支持的扩展名 |
| --- | --- |
| PDF | `.pdf` |
| 表格 | `.xla`、`.xlb`、`.xlc`、`.xlm`、`.xls`、`.xlsx`、`.xlt`、`.xlw`、`.csv`、`.tsv`、`.iif`、`.numbers` |
| 文档/富文档 | `.doc`、`.docx`、`.dot`、`.odt`、`.rtf`、`.pages` |
| 演示文稿 | `.pot`、`.ppa`、`.pps`、`.ppt`、`.pptx`、`.pwz`、`.wiz`、`.key` |

PDF 附件支持 `auto`、`low`、`high` 三档 `detail`。其他文件不会携带 PDF 专用参数。

### 文本和代码文件

以下扩展名会作为原始文件发送，不会在本地提取或拼接正文：

```text
.asm .bat .c .cc .conf .cpp .css .cxx .def .dic .eml .h .hh .htm .html
.ics .ifb .in .js .json .ksh .list .log .markdown .md .mht .mhtml .mime .mjs
.nws .pl .py .rst .s .sql .srt .text .txt .vcf .vtt .xml .ts .tsx .jsx
.java .go .rs .php .rb .sh .bash .zsh .tex .cs .scala .kt .kts .swift .lua
.r .jl .ex .exs .erl .hrl .hs .clj .groovy .dart .awk .hbs .mustache .ejs
.jinja .jinja2 .liquid .erb .twig .pug .jade .cmake .gradle .ini .properties
.proto .scss .sass .less .hcl .tf .toml .graphql .gql .ndjson .json5 .yaml
.yml .astro .diff .patch .dockerfile
```

- 文件名为 `Dockerfile`（没有扩展名）时也会被识别为代码文件。
- 常见文本、代码、Office、表格和演示文稿 MIME 类型也会参与识别。
- 当扩展名与 MIME 类型不一致时，客户端会根据文件名推断安全的发送 MIME 类型。

### 文件大小与上游要求

- 单个文件必须严格小于 50 MB。
- 同一条请求中的全部文件合计也必须严格小于 50 MB。
- Base64 会使 JSON 请求体约增加三分之一；反向代理或中转站建议将请求体上限设置为至少 72 MiB。
- 上游必须支持 `/v1/responses` 的 `input_file.file_data`；不支持该能力的 Endpoint 无法读取这些非图片附件。
- PDF 中的扫描页、图片和图表需要模型具备视觉输入能力；非 PDF 文档中的嵌入图片和图表不保证进入视觉上下文，需要保留版式时建议先转换为 PDF。

## 兼容性

- 文件上传白名单、原生 `input_file` 请求结构、PDF `detail` 语义和大小限制均未改变。
- 没有恢复已经删除的浏览器端或服务端本地文件解析逻辑。
- 更新日志仍由仓库内的 Markdown 发布说明提供，旧版本发布说明无需迁移即可继续展示。

## 验证

- `npm run check`：项目检查、架构边界检查、语法检查和 620 项自动化测试全部通过。
- 桌面端与 390px 移动端完成实际浏览器截图检查；移动端页面宽度保持为 390px，宽表格在日志卡片内部独立滚动。
- 已验证日志弹窗覆盖常驻悬浮入口，同时不改变路由图主弹窗的最高层级。
