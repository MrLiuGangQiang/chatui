# 07 测试与质量门禁

## 1. 测试分层

| 层 | 目录 | 内容 |
| --- | --- | --- |
| unit | `test/unit/` | 纯函数、模块、契约、状态机、错误分支、可注入依赖 |
| smoke | `test/smoke/` | 启动真实 HTTP server 的跨模块链路 |
| fixtures | `test/fixtures/` | 稳定、无秘密的输入 |
| legacy | `test/legacy/` | 历史回归，只出不进 |

`test/run-tests.js` 是唯一标准测试入口。suite 必须导出非空命名 `test*` 函数数组。

## 2. 运行命令

```bash
npm run check                 # 项目 + 架构 + 语法 + 全部测试
npm test                      # 全部测试
npm test -- server-hardening  # 按路径/文件名片段聚焦
node test/run-tests.js unit/<name>.test.js
```

直接执行 suite 文件不经过 runner，不能作为测试证据。默认单项超时 10s。

## 3. 命名与断言

- 测试名描述行为与期望，不描述实现细节。
- 优先调用真实导出并断言结果；源码字符串断言只用于必须冻结的装配/缓存/发布/兼容约束。
- 断言日志文件前必须 `await logger.flush()`。

## 4. 质量门禁（强制）

每个修复必须：

1. 为**该精确失败模式**写专属回归测试；
2. 证明它**在修复前失败**、**修复后通过**（先红后绿）；
3. 把测试接入 `npm run check` 与 CI。

没有对应质量门禁的修复视为未完成。涉及架构、缓存、发布或协议时，同时更新 `docs/design/` 与深文档。

## 5. 覆盖要求

- 核心链路必须有回归：静态/bundle 与缓存、路由与执行契约、任务生命周期与恢复、会话持久化、安全归属、日志脱敏、发布身份。
- 新增公共模块必须可被 Node 独立加载测试；浏览器 UI 行为优先抽纯逻辑测试。
