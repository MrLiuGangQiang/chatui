# 14 固定文件公告设计

> 状态：已按“只认固定文件名”收敛  
> 日期：2026-09-14

## 1. 范围与目标

公告只使用一个固定文件名：

```text
data/announcements/announcement.md
```

- 目录中的其他 Markdown 文件一律不读取；
- 不展示历史公告，不做文件排序；
- 修改固定文件内容后，内容指纹变化，会重新触发未读/强制阅读，并通过 SSE 即时通知已打开页面；
- 文件不存在、标题为空或正文为空时，返回空公告，不阻塞主应用；
- 同目录的 `model-recommendation.json` 继续负责推荐模型展示。

非目标：

- 不新增数据库、管理后台、登录、权限、审批、定时发布或历史页面；
- 不引入 WebSocket、推送服务或浏览器轮询定时器；
- 不在浏览器中直接读取宿主机目录；
- 不改变聊天、图片、任务、路由或代理契约。

## 2. 固定文件与模板

固定文件名：

```text
announcement.md
```

文件内容：

```markdown
---
published_at: 2026-09-10
badge: 系统公告
summary: 这里填写一句话摘要
---
# 这里填写公告标题

这里填写正文，支持现有公告中心的 Markdown。
```

`_template.md` 只用于复制模板，`README.md`、`model-recommendation.json` 和其他文件名都不会作为公告。

## 3. 读取与推送流程

```text
GET /api/announcements
  -> 只读取 CHATUI_ANNOUNCEMENTS_DIR/announcement.md
  -> 解析 front matter、一级标题和正文
  -> 计算内容指纹，作为 version/已读键
  -> 返回 0 或 1 条公告

GET /api/announcements/events
  -> 建立公开 SSE 连接并立即发送当前公告快照
  -> fs.watch 监听公告目录中 announcement.md 的变化
  -> 去抖后重新读取，内容指纹变化时广播同一快照结构
```

- 文件不存在、不可读、超过 256 KiB、缺少标题或缺少正文：返回空数组。
- 没有公告时，公告中心显示“暂无公告”，主应用正常进入。
- 修改 `announcement.md` 的任意有效内容：`version` 立即变化，SSE 将新快照推送给所有在线页面，未读页面立即重新触发强制阅读。
- 浏览器启动时只执行一次 `GET /api/announcements` 获取权威快照，随后保持一条 `EventSource`；不得保留 5 分钟轮询定时器。
- 页面激活后的公告刷新是 best-effort：启动快照已初始化后，即使刷新请求瞬态失败，也不得重新打开强制公告遮罩或锁定应用；保留当前已确认的空/非空快照，等待 SSE 或下一次激活刷新收敛。
- SSE 重连后服务端先发送当前快照，因此客户端无需依赖断线期间的增量回放；页面 focus、pageshow、恢复可见或网络恢复时仍执行一次事件驱动快照刷新作为兜底。
- 推荐模型文件和其他目录变化不会触发公告事件；只有公告快照的内容指纹变化才广播。

## 4. API 契约

`GET /api/announcements` 响应结构保持不变，数组最多一个元素：

```json
{
  "announcements": [
    {
      "version": "announcement-0123456789abcdef",
      "title": "公告标题",
      "summary": "一句话摘要",
      "publishedAt": "2026-09-10",
      "badge": "系统公告",
      "body": "# 公告标题\n\n正文"
    }
  ]
}
```

响应必须为 `no-store`。`version` 是 `announcement.md` 的内容指纹，不要求运营人员手动维护版本号。

`GET /api/announcements/events` 是公开只读 SSE：

- 响应使用 `text/event-stream`，保持 `no-store` 与 `X-Accel-Buffering: no`，服务端每 5 分钟发送注释 keepalive；反向代理的空闲读取超时必须大于 5 分钟，否则连接会按代理策略断开并由 EventSource 自动重连；
- 连接建立和公告变化均发送同名 `announcement` 事件，`data` 与 `GET /api/announcements` 的响应结构一致；
- 非空公告使用 `id: announcement-...` 标记内容指纹；空公告不保留旧 id；
- SSE 只承载公告快照，不增加鉴权、用户数据或服务端持久化状态。

## 5. 部署方式

### 本地开发

直接编辑：

```text
data/announcements/announcement.md
```

保存后在线页面通过 SSE 接收新公告；刷新页面仍可读取当前快照。

### Docker

```bash
docker run -d \
  --name chatui \
  --restart unless-stopped \
  -p 8765:8765 \
  -v /srv/chatui/announcements:/app/data/announcements:ro \
  liugangqiang/chatui:latest
```

多实例部署时应挂载同一个共享目录，或在发布后同步该文件。`fs.watch` 的跨容器通知能力取决于共享卷实现；不能保证通知的网络卷仍以页面激活时的快照刷新作为兜底。

## 6. 安全与边界

- 公告目录只读，服务端不创建、不修改、不删除公告文件。
- 固定文件最大 256 KiB；不递归读取子目录。
- SSE 接口公开只读，只发送公告快照；不得附带 principal、其他用户数据、API Key 或内部路径。
- 仅公告快照变化时广播；非法或空公告按空快照处理，不能让监听目录中的其他文件影响公告流。
- 正文继续经过公告中心现有 Markdown 消毒与链接策略。
- 公告正文不得包含 API Key、数据库连接串或其他秘密。
- `/data/` 不进入静态服务器公开路径。
- 旧 `docs/announcements/` 源码不再复制进 Docker，不参与运行指纹，也不进入接口。

## 7. 验收标准

1. 修改固定文件 `announcement.md` 后，`GET /api/announcements` 返回一条公告，无需改版本号、重新构建或重启服务。
2. 同名文件内容变化后，`version` 内容指纹变化，已读用户再次看到强制阅读。
3. 其他 Markdown 文件名即使存在，也不会进入接口。
4. 文件不存在、标题为空、正文为空或超过 256 KiB 时，接口返回空数组，主应用正常可用。
5. 不显示历史公告入口或历史列表。
6. 公告内容不改变 `version.json`、bundle 指纹、Docker 运行指纹或镜像身份。
7. `model-recommendation.json` 可独立更新推荐模型展示。
8. 公告正文中的图片点击后在当前页面的统一图片预览层打开，不得新开浏览器页面。
9. 公告中心在桌面端铺满当前视口，正文、标题与操作区保持足够的阅读间距；窄屏继续使用全屏单列布局。
10. 全屏公告保留原有双栏内容与辅助说明，仅调整栏宽、内边距、字号和滚动边界，避免铺满视口后出现压缩、裁切或大面积空白。

11. 手机端公告采用全屏单列布局并隐藏推荐模型、重要说明等辅助区，只保留公告标题、正文和阅读操作；标题区与底部操作区占满可用宽度，仅正文区域承担纵向滚动，顶部与底部安全区、44px 关闭按钮和至少 48px 的主要操作按钮必须在窄屏下保持可用。
12. 修改固定文件后，已打开页面无需刷新即可在 SSE 事件到达后显示新公告；浏览器取消 5 分钟轮询，仅保留启动快照和页面激活时的兜底刷新。

## 8. 回归测试

- `test/unit/announcement-directory.test.js`
  - 只读取 `announcement.md`；
  - 内容变化会改变 `version`；
  - 其他文件名、模板、非法文件和超限文件被忽略；
  - 文件缺失返回空数组。
- `test/unit/announcement-center.test.js`
  - 公告中心只基于固定文件触发强制阅读；
  - 无公告时显示“暂无公告”并放开主应用；
  - EventSource 推送的新公告立即重新触发强制阅读，非法推送不覆盖最后有效快照；
  - Docker 不再复制旧 `docs/announcements`；
  - 公告图片使用当前页面图片预览层，不调用新窗口/新页面。

  - 文件删除广播空快照；默认 5 分钟心跳；关闭服务时结束连接和 watcher。
- `test/unit/runtime-build-identity.test.js`
  - 旧公告文件不参与 Docker 运行指纹。
- `test/unit/api-contract.test.js`
  - `/api/announcements` 返回最多一条公告且保持 `no-store`。

## 9. 实施边界

- 不修改 `index.html`、`app.js`、`styles.css`、`server.js` 等受保护根静态入口中与公告无关的部分。
- 不新增浏览器全局变量和前端构建步骤。
- 同步更新 `docs/development.md`、`README.md`、`docs/architecture.md` 和对应设计索引。
- 功能本身只需一次正常发版；之后只修改固定文件 `announcement.md`。

## 公告图片资源

公告目录支持同级 `images/` 子目录中的只读图片资源。宿主机挂载到容器 `/app/data/announcements` 后，公告正文可使用：

```markdown
![更新截图](/announcements/images/update.png)
```

服务端只开放 `/announcements/images/` 路径，并限制在公告目录内，拒绝路径穿越；图片不进入公告 API 响应。
