# ChatUI v2.0.0

## 变更

- 意图识别升级为“理解 → 路由 → 校验/修复”双节点思维链：理解节点（`intent_understanding.v1`）与路由节点（`route_intent.v3`）使用各自独立的系统提示词，复杂路径与简单路径都不再发送旧的单次巨无霸提示词；理解证据存在时路由节点使用精简 CoT 提示词（≤2500 字符），简单路径使用独立精简版，仅当理解失败或动作输出为空时才回退完整版单跑。
- 路由节点新增确定性语义校验与定向修复：quoted 证据存在时 relation 必须为 followup、relation=new 与资源引用矛盾、amend 无前序基础任务、单 action 的 operation 与 kind 映射不一致等都会被自动修正；主模型与 fallback 模型共用同一套校验与修复路径，修复轮次使用独立的 `route_repair`/`route_fallback` 等请求用途并写入访问审计（仅稳定 code，不含正文）。
- 图片多结果兜底：即使理解模型把多图请求合并为一条 action，Shape Compiler 仍按原文显式输出结果数量提升为图片计划（如“把 N 张图改成黑白”“分别/各自/每个”“第 1 张和第 5 张”、视图枚举），且不会把输入图数量或画面主体误判为多个结果。
- 自由文本澄清回答：只询问开放式文本、没有选项的澄清（如“什么品种/毛色/姿态”）现在可以直接用文本回答，包括“你随机”委托系统决定；回答后立即关闭待处理澄清（`answer_complete=true`、`free_text` 记录回答），不再无限重复追问。
- 多任务请求拆分更稳定：编号选择支持中文数字，任务拆解不忠实时自动修正；选中任务直接携带对应的文件/图片资源执行，不再丢失绑定。
- 同一轮对多张图片提同一个问题（如“第二张和最后一张是什么颜色”）会合并为一次识图，不再拆成多个任务；等待提示会显示当前所处阶段（读取上下文、理解请求、判断意图、拆分任务等）。
- 编辑后重发与重新生成现在也走意图识别，行为与新发送一致；多任务计划在刷新页面后可恢复，继续选择未执行的任务；会话提示词/模型按钮在启用时保持可见的激活状态。
