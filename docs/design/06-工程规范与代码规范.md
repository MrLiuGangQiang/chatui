# 06 工程规范与代码规范

## 1. 仓库结构

```text
client/core/ services/ ui/ features/ app/ config/   浏览器分层代码
server/api/ services/ jobs/ http/ proxy/ security/ usage/ db/ validators/ logging/ config/ errors/
shared/                                              双端安全契约与常量
vendor/                                              第三方浏览器资产
styles/ pages/ config/public.json                   样式、独立页面与公开配置
test/unit/ smoke/ fixtures/ helpers/ run-tests.js
scripts/                                            检查、发布与验证脚本
docs/ architecture.md development.md design/ releases/ announcements/
index.html app.js styles.css server.js              受保护根静态入口
```

## 2. 编码风格

- UTF-8、LF、两空格缩进、文件末尾换行。
- 小模块、单一职责；优先兼容门面，不要复制一份实现。
- 标识符英文；注释与用户文档中文。注释解释"为什么"和非显然约束，不复述代码。
- 禁止新增 `with (...)`；禁止新增 `window.ChatUI*` 全局导出。
- 不手工修改 `vendor/` 压缩文件。

## 3. 命名约定

| 项 | 约定 |
| --- | --- |
| 文件 | camelCase（`route-intent-workflow.js`），测试 `*.test.js` |
| 常量 | UPPER_SNAKE；协议字段 snake_case |
| 版本 | `vX.Y.Z`；发布说明 `docs/releases/vX.Y.Z.md` |
| 提交 | `feat:/fix:/perf:/refactor:/chore:/release: vX.Y.Z ...` |
| 测试函数 | `test<ObservedBehavior>`，描述可观察行为 |

## 4. 模块加载与 registry

- 浏览器脚本必须出现在 `index.html` 的 `chatuiAssetManifest`；Node 测试辅助代码不得进 bundle。
- 新模块经 registry 注入依赖，不新增浏览器全局。
- `server/services/static-bundle.service.js` 是 bundle 元数据的唯一组装者。

## 5. 错误与用户文案

- 服务端错误统一走 `server/errors/http-error.js`；不再增加只做转发的错误模块。
- 用户可见文案平实、可行动；诊断码只进日志。错误分类按 04 §7 六类，不误导用户。

## 6. 提交与 PR 检查清单

- [ ] 最小改动，已定位并验证根因
- [ ] 不违反 02 依赖方向与根静态入口规则
- [ ] 每个修复带专属回归测试（07）
- [ ] 无密钥/日志/生成产物提交
- [ ] `npm run check` 通过；脚本、CI、Docker、文档同步
- [ ] 设计变更已更新 `docs/design/` 对应文档
