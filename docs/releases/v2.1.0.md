# ChatUI v2.1.0

ChatUI v2.1.0 是 2.0.x 之后的功能性版本：重构了意图识别与路由链路，加入多实例部署的在线人数支持，并更新了公告中心提示与若干体验细节。

## 意图识别与路由重构

- 默认请求走最小决策链：普通单任务只调用一次意图路由模型，不再串行执行 understanding、critic 与 image planning，明显降低请求延迟。
- 高风险/复杂请求启用自适应推理：先路由、再语义审查，只有审查失败才进入定向修复；修复有预算和 deadline，绝不无限循环。
- 新增内部语义证据合同 `semantic_intent.v1`、`intent_critic.v1` 与字段级修复协议 `route_repair.v1`：修复只允许修改被授权的字段，越权或修复失败时保留原始基线，最终以 `invalid_model_output` 失败关闭，绝不执行被破坏的路由。
- 单图片/单文件问答收敛为 `image_qa` / `file_qa` 单任务；"读取图片/文件"作为证据使用，不再被拆成额外任务。
- 缺失正文、缺失附件等输入不完整情况，在模型调用前直接给出业务澄清，不伪装成其他资源类型。
- 模型输出无效时不再回退到本地关键词路由，保持 fail closed 的诚实失败分类。
- 意图识别过程展示可折叠的结构化决策轨迹（`intent_reasoning.v1`），终态默认收起可展开查看；等待态只保留一个 live surface，原位覆盖更新，并遵循 `prefers-reduced-motion`。

## 在线人数多实例支持

- 新增 `REDIS_URL` 配置：多副本部署时，在线人数保存在 Redis 共享有序集合，任一实例的 join/leave/heartbeat 都会正确计入全局在线数，并通过 pub/sub 广播到所有实例。
- 未配置 `REDIS_URL` 时保持原单实例内存逻辑，行为不变。
- Redis 不可用时 presence 接口返回 503 不可用状态，不影响聊天、生图和附件等核心功能。

## 公告与提示更新

- 公告中心标题显示当前运行时版本（基于 `__CHATUI_RUNTIME_IDENTITY`）。
- 提示文案更新：理解有偏差时请清晰指定任务目标，并可更换更高级的意图识别模型。
- 新增提示：生图时如果给出的内容有歧义、容易误导大模型，可以直接点击"强制生图"。

## 体验与稳定性

- 新增意图等待态与决策轨迹样式（calm/flat 主题），等待动效在减少动态效果设置下关闭。
- 图片会话切换后的历史图片恢复、批处理状态展示等细节改进。
- 配套新增/调整多组单元测试与回归门禁，`npm run check` 全量通过。
