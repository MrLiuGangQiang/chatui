# 03 数据模型与持久化设计

> 浏览器侧本地持久化是核心；PostgreSQL 只承担可选的使用统计，未配置时显式不可用。

## 1. 存储分层

| 存储 | 用途 | 边界 |
| --- | --- | --- |
| `localStorage` | 配置、会话元数据、消息文本、任务恢复、UI 状态 | 不放大体积二进制 |
| `data/announcements/`（可挂载目录） | 运行期公告 Markdown 与 `model-recommendation.json` | 部署方维护的只读数据；不进入版本校验、数据库或浏览器持久化 |
| `IndexedDB`（`openapi-chat-image-db-v1`） | 生成图片与附件二进制缓存 | 只存可重取/可备份的媒体 |
| PostgreSQL（可选） | 使用统计与排行榜 | 数据库未配置时统计显式不可用，不影响聊天/图片/静态页 |

写入 `localStorage` 前，消息 HTML 中的大体积 Base64 数据 URL 必须被替换为省略标记。清理逻辑必须按输入线性扫描，不得对整条消息 HTML 执行无界贪婪正则，避免大图预览在持久化阶段触发 JavaScript 引擎栈溢出。

## 3. 会话与消息模型

会话对象（`client/app/state.js`）至少包含：`id`、`title`、`customTitle`、`messages`、`display`、`systemPrompt`、`imageStylePrompt`、`chatModel`、`promptDraft`、`reasoningMode/Type`、时间戳与 `busy`。消息以稳定的 turn/message 身份存储，导入与恢复用墓碑标记删除项，避免重复或丢失。

## 4. 任务与恢复

- job kind：`chat` / `image` / `image-batch`；服务端为权威运行时，浏览器侧保存恢复元数据。
- 未完成提交（pending）在刷新后按会话重建；任务预算、幂等键与终止态由服务端校验。
- “已完成回答”判定必须要求非 pending 且存在有效正文文本或 durable 富媒体；空文本和纯状态文案不能作为完成证据。编辑重发/重新生成留下的空 replacement 槽位不得清除仍在运行的 chat job。
- 会话切换复用 pending DOM 缓存时，已有节点必须按最新 `messageIndex/responseIndex` 重新定位；缓存命中只允许复用节点内容，不得保留过期的消息顺序。
- 图片批量使用 `image_task_lineage.v1` 为每个子任务单独保存 lineage，不把批次末项伪装成整个批次的前序。
- 图片结果的远端二进制必须先有界读取、直连超时后经 `/api/image` 回退并写入 IndexedDB，之后才提交 canonical `image_result.v1`；网络或本地写入失败必须给出可操作错误，不能留下永久 pending 投影。
- 图片结果提交 canonical 后，活动会话必须重新检查最终 DOM 是否实际承载 `generated-thumb`；临时节点即使仍连接、但无法接受富媒体 HTML 时，也必须立即执行一次 canonical 渲染，不得要求用户刷新页面。
- 图片任务在服务端明确返回 4xx 拒绝且尚未获得 managed job id 时，必须清除本地 durable snapshot 和 pending 投影并进入错误态；只有创建结果不确定的网络/5xx 场景才保留恢复快照。
- `intent_reasoning.v1` 默认作为本轮临时显示状态随路由生命周期存在；若进入澄清或可恢复 pending，只允许保存脱敏后的阶段摘要、稳定 reason code 和必要的终态，不保存完整模型输出或凭据。

## 6. 变更纪律

- 浏览器存储结构变更必须向后兼容：读取旧结构、显式迁移、导入重置墓碑，禁止静默丢弃。
- 大字符串的持久化清理必须保持有界且可预测；不得以捕获异常掩盖引擎资源错误。
- 附件进入草稿前的单文件/合计大小限制和图片压缩策略遵循 17；超过限制的附件不得写入 IndexedDB、消息 HTML 或 localStorage。
- 协议字段变更必须升版本并保留旧版本迁移路径，禁止新增业务默认值。唯一例外是 `image_instruction.v1` 中由 `status` 唯一要求为空的伴生字段：JSON-mode 供应商省略该字段时只在协议解析边界补 `''`，语义必需字段、额外字段和相互矛盾值仍必须失败关闭。
- 删除或移动 key 前先核查测试、备份/导入与任务恢复消费者。
