# 01 设计原则与约束

> 本文档是 ChatUI 从设计到实现的判定依据，所有架构决策、代码评审与变更评估首先对照这里。

## 1. 文档目的

- 固化项目定位与边界，避免范围蔓延和补丁式修复。
- 固化无构建、单服务、可直部署的架构纪律。
- 让"为什么这么做"可追溯，不依赖口头约定。

## 2. 项目定位

**ChatUI：轻量、无构建、可直接部署的 OpenAI 兼容 Web 工具。** 单页前端 + Node.js 本地代理，支持聊天、流式输出、思考内容、文本生图、图片编辑、多附件、Markdown/公式/图表、会话、任务恢复、本地图片缓存、使用统计与 Docker 发布。

## 3. 设计原则

| 编号 | 原则 | 落地点 |
| --- | --- | --- |
| P1 | **无构建、单源部署** | Node 服务同时提供根 HTML、动态 bundle、模块/样式/vendor 资源和 OpenAI 兼容代理；不引入 `dist/` 或前端构建步骤 |
| P2 | **单向依赖、边界清晰** | `client/core → services → app/ui` 与 `server/api → services → jobs/http` 分层，`shared/` 仅放双端安全代码；浏览器模块经 registry 组装 |
| P3 | **契约先行、协议版本化** | 意图、执行、任务连续性等跨层契约带版本（如 `route_intent.v3`、`dispatch_contract.v1`），双端校验，禁止静默补默认值 |
| P4 | **失败关闭、安全默认** | 路由协议无效时不本地猜测执行；输入消毒、principal 任务归属、CSP、代理路径白名单默认开启 |
| P5 | **可观测、脱敏** | access/error/server/request-trace 使用有界异步 NDJSON writer；密钥、base64、签名 URL 参数不落盘 |
| P6 | **数据可恢复** | 会话/消息/图片本地持久化，任务可刷新恢复，支持备份导入与墓碑，异常时保守恢复 |
| P7 | **可测试、门禁先行** | 每个修复带专属回归测试，先证失败再证通过，接入 `npm run check` 与 CI |
| P8 | **兼容与演进** | 旧协议只允许显式适配迁移；架构基线冻结 `app.js` 大小、`with` 与浏览器全局增长 |
| P9 | **规范统一** | 命名、响应、结果分类、缓存策略、发布说明全项目一致 |
| P10 | **杜绝补丁式修复** | 任何问题先定位根因，在正确架构层修正；症状屏蔽与特例绕过不通过 |

## 4. 硬性约束

1. **版本单一来源**：`version.json` 是唯一版本事实；`package.json`/`package-lock.json` 只是 npm 镜像，发版必须走 `npm run release:prepare`，禁止手工改版本。
2. **无构建步骤**：`index.html` 的 `chatuiAssetManifest` 是资源清单，`server/services/static-bundle.service.js` 在请求时组合 `/assets/chatui.bundle.js|css`。
3. **根静态入口受保护**：`index.html`、`pages/route.html`、`pages/files.html`、`app.js`、`styles.css`、`favicon.svg`、`server.js` 必须与静态服务、Docker 镜像、测试和文档同步变更。
4. **端口固定**：本地开发与手动测试服务一律使用 `8765`；占用时报告占用进程，不自动换端口。
5. **路由失败关闭**：意图模型输出无效时禁止本地关键词路由兜底；结果只允许 `ready / business_clarification / configuration_error / transient_error / invalid_model_output / cancelled` 六类，配置或网络错误不得伪装成澄清。
6. **依赖方向**：遵守 02 的禁止方向清单；`shared → client/server`、`client → server`、低层契约反向依赖高层工作流均禁止。
7. **模块注册**：不新增 `window.ChatUI*` 全局导出；浏览器代码经 module registry / manifest 组装。
8. **vendor 边界**：`vendor/` 只放第三方浏览器资产，不放应用代码或凭据，不手工修改压缩文件。
9. **密钥与日志**：私密配置放 `.env.local`（被忽略，只补缺不覆盖部署变量）；API Key、Authorization、文件/图片 base64、签名 URL 查询参数不得进入日志或 Git。
10. **质量门禁**：修复不附带"先红后绿"回归测试视为未完成。
11. **测试分层**：新测试只进 `test/unit/` 或 `test/smoke/`；`test/legacy/` 已移除，不得恢复。
12. **提交清洁**：不提交生成报告、日志、IDE 状态或密钥。

## 5. 技术栈选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 运行时 | Node.js `>=20.19.0`（`.nvmrc`/Docker 用 22） | 无框架，Node `http` 核心 |
| 浏览器 | 原生脚本 + module registry | 无 bundler；服务端动态拼接 bundle |
| 服务端依赖 | `jszip`、`pg`、锁定 `undici@7.29.0` | 仅生产运行所需 |
| 浏览器依赖 | 提交在 `vendor/`（DOMPurify、markdown-it、KaTeX、highlight.js、Mermaid） | 重度增强按需加载 |
| 存储 | 浏览器 localStorage + IndexedDB；可选 PostgreSQL | 无数据库时使用统计显式不可用，不影响核心功能 |
| 测试 | 自研 runner `test/run-tests.js` | unit + smoke |
| 部署 | Docker；ACR + Docker Hub | 候选 digest 验证后原样提升 |

## 6. 架构决策记录（ADR）

| ADR | 决策 | 理由 |
| --- | --- | --- |
| ADR-001 | 无构建，服务端按 manifest 组合 bundle | 部署极简，源与运行时一致 |
| ADR-002 | 单 Node 服务同时提供静态与代理 API | 无前后端拆分，降低运维面 |
| ADR-003 | 内容寻址 bundle 长缓存，入口保持 no-store | 刷新免重下，内容变更自动换 URL |
| ADR-004 | 意图识别"理解 → 路由 → 校验/修复"双节点 | 质量优先，协议无效时失败关闭 |
| ADR-005 | principal cookie 承载任务归属 | 无登录态也能隔离不同用户的任务 |
| ADR-006 | PostgreSQL 仅承担使用统计且可选 | 核心功能不依赖外部数据库 |
| ADR-007 | 有界异步日志 writer + 独立队列 | 洪峰不阻塞请求、不无限占内存 |
| ADR-008 | 每个修复必须有专属回归门禁 | 用测试固化根因，防止回潮 |
