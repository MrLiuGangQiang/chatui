# 00 设计文档索引与使用规则

> `docs/design/` 是 ChatUI 的规范层：定义定位、原则、硬约束、架构决策、契约与交付门禁。实现必须服从本目录；任何影响这些内容的变更必须同步更新本目录。

## 2. 与既有文档的关系

- `docs/architecture.md`：模块边界的实现细节与当前事实，是 02 的展开。
- `docs/development.md`：命令、环境变量、测试 runner 的详细说明。
- `docs/intent-recognition-cot-design.md`：意图识别的唯一参考功能设计。
- 决策与约束以 `docs/design/` 为准；细节以对应深文档为准。两者冲突时，应视为设计变更：本目录与深文档在同一提交中一起修正。

## 3. 变更门禁（设计先行）

影响架构、数据/协议、API、安全、发布流程或用户可见行为的变更，提交必须同时包含：

1. 更新对应设计文档（以及受影响的深文档）；
2. 说明根因与边界取舍；
3. 为该失败模式新增回归门禁（见 07）；
4. 更新包脚本、CI、Docker 验证与文档的一致性。

## 4. 新功能设计模板

新功能以 `NN-<功能>-设计.md` 加入本目录，至少包含：

- 范围与原则（做什么、不做什么、失败语义）；
- 流程图 / 状态机（跨模块交互与终态）；
- 契约与数据模型（版本化 schema、存储 key、迁移/兼容策略）；
- API 与缓存语义；
- 安全与可观测性；
- 验收标准与专属回归测试清单。
