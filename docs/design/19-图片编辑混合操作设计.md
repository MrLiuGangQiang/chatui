# 19 图片编辑混合操作设计

> 状态：设计基线，已进入实现。
> 日期：2026-09-12
> 关联文档：`16-图片编辑工具设计.md`、`18-图片清晰度提升设计.md`、`04-API与服务契约设计.md`

## 1. 范围与目标

图片编辑工作台从单工具提交升级为混合操作：

- 评论、局部擦除、调整尺寸和画质提升可以在同一次编辑中组合；移除背景因模型透明输出能力限制，必须单独执行；
- 评论和局部擦除可以累计多条；
- 移除背景和画质提升每次编辑最多各添加一条；调整尺寸也最多保留一条并替换旧选择；点击工具栏选中并添加记录，再次点击同一全局工具取消并移除记录；
- 右侧“评论”区域改为“操作历史”，按固定语义顺序（评论 → 局部擦除 → 画质提升 → 调整尺寸 → 移除背景）展示全部操作；
- 点击“提交修改”时只发起一次确定性的 `edit_image` 请求，不需要用户重复操作。

非目标：

- 不把整体清晰度提升和背景移除拆成多次模型调用；
- 移除背景与其他操作混用时不做隐式拆分或自动重试，直接提示用户单独执行移除背景；
- 不新增服务端接口、任务类型或数据库字段；
- 不允许移除背景或画质提升在同一编辑会话中重复出现；
- 不保证像素级超分辨率；混合提示词仍受上游图片编辑模型能力限制。

## 2. 流程与状态

```text
打开图片编辑器
  -> 点击评论 / 选择局部擦除：添加局部操作历史
  -> 点击移除背景：添加全局背景记录（最多 1 条）
  -> 点击画质提升：添加全局清晰度记录（最多 1 条）
  -> 点击调整尺寸：选择宽高比并添加尺寸记录（最多 1 条）
  -> 右侧“操作历史”按顺序显示
  -> 点击提交修改
      -> 若移除背景与其他记录同时存在：不生成 mask/请求，提示“请单独使用移除背景”
      -> 合并评论圆 + 擦除笔迹为一张 alpha mask
      -> 合并全局处理与局部修改为同一 edit prompt
      -> 传入 background=transparent / output_format=png（仅移除背景时）
      -> 一次 edit_image 任务返回一张最终图片
```

状态：

```text
{
  activeTool: 'comment' | 'erase' | '',
  strokes: [],
  comments: [],
  operations: { remove_background: boolean, enhance: boolean, resize: preset },
  history: [comment | erase | operation]
}
```

- 评论和擦除用于画布交互，可继续累计；
- 全局操作是幂等开关，不因重复点击产生重复记录；
- 撤销移除最后一条操作历史；
- “重置”按产品约定清空全部记录并回到初始状态；不拦截 Ctrl/Cmd+Y 与 Ctrl/Cmd+Shift+Z 作为破坏性快捷键。

## 3. 数据与请求契约

- `operation=edit_image`、`api=image_edit`；
- 始终只有一张 `role=target`；
- 存在评论或擦除记录时，生成一张 `role=mask` 的 PNG；评论圆和擦除笔迹取并集；
- 只有全局操作时不生成 mask；
- 提示词按固定语义顺序写成一条完整编辑指令，不使用“步骤 N / 上一阶段 / 后一步”等多阶段措辞，避免图片模型把透明背景误画成棋盘格：
  1. 先处理评论和局部擦除：只修改编辑蒙版透明区域；评论使用编号坐标，擦除记录从笔迹计算归一化中心、边界与画面方位，并写入“选中区域位置 + 修改内容 + 蒙版外保持不变”结构；
  2. 随后画质提升：增强整图细节、纹理、边缘和局部对比度，同时保持构图、主体、颜色、光照、风格和文字不变；
  3. 最后调整尺寸：按选定比例和输出尺寸自然扩展、补全或重新构图，保持主体、颜色、风格和细节；
  4. 移除背景：将整张图背景设为透明，保持前景主体、文字和边缘完整。
- 执行提示词必须自足；无法证明“前一步 / 上一阶段”等序列引用已在同一执行指令中声明时一律拒绝，不能包含依赖历史对话、历史结果或未提供图片才能消解的引用；真正的跨轮引用必须在进入执行层前物化，不得透传给图片 provider；
- `background=transparent`、`output_format=png` 仅在移除背景被选中时添加；
- 移除背景必须作为唯一操作提交；存在评论、擦除、画质提升或调整尺寸时，提交门禁必须拒绝，不能构造混合背景移除 prompt；
- 用户消息显示操作历史列表，例如：

```text
提升图片清晰度
移除图片背景
1. 淡化左侧水面
局部擦除：去掉右上角文字
```

## 4. UI 与状态呈现

- 右侧标题为“操作历史”，数量胶囊显示全部记录数；
- 记录固定按“评论 → 局部擦除 → 画质提升 → 调整尺寸 → 移除背景”的执行顺序展示，不按点击先后无序混排；
- 评论记录保留随机颜色编号、标题和说明；
- 擦除记录显示擦除图标、说明；
- 移除背景和画质提升各显示一条带图标的操作记录；
- 工具按钮采用多选状态：评论/擦除按钮表示当前画布交互模式，全局操作按钮表示已加入/未加入的记录；
- 全局工具按钮是可见的开关：再次点击已选中的“移除背景”或“画质提升”会取消选择并移除记录，不会产生第二条记录；
- 评论、擦除、移除背景、画质提升和调整尺寸记录均可单独删除；评论记录可编辑，其他记录不能编辑；
- 当移除背景与其他操作同时存在时，点击“提交修改”保持编辑器开启并提示用户单独使用移除背景；
- 空列表显示“暂无修改，选择工具添加记录”。

## 5. 安全与错误边界

- 混合操作仍由编辑器按钮发起，不经过意图模型；
- mask 只包含用户明确绘制的评论位置和擦除笔迹，不扩大编辑范围；
- 图片、mask、提示词沿用现有日志脱敏和代理白名单；
- 存在评论或擦除记录时缺少 mask 必须失败关闭；仅有画质提升或移除背景的全局操作时无 mask 是合法状态；目标图或提示词缺失时始终失败关闭；
- 移除背景与其他操作混用时必须在本地提交边界失败关闭，不发送请求；提示不得伪装成模型执行失败或澄清；
- 上游失败沿用既有中文可操作提示，不伪装为成功。

## 6. 验收标准

1. 评论、擦除、画质提升和调整尺寸可在同一编辑会话中混合；移除背景只能在没有其他操作时提交；
2. 评论和擦除可添加多条，移除背景、画质提升和调整尺寸各最多一条；
3. 右侧显示“操作历史”并按固定语义顺序列出记录；
4. 点击应用只发起一次 `edit_image`；
5. 局部记录存在时只发送一张合并 mask，评论圆与擦除笔迹都包含在 mask 中，提示词同时包含评论坐标和每条擦除记录的归一化位置；
6. 单独移除背景时请求包含 `background=transparent` 与 `output_format=png`；与其他操作混用时不创建请求并显示明确提示；
7. 提示词严格按“评论和局部擦除 → 画质提升 → 调整尺寸 → 移除背景”排列，但不得使用编号步骤、上一阶段或后一步等会诱发棋盘格的多阶段措辞；
8. 混合提示词可独立执行；真正的跨轮引用仍由执行边界拒绝；
9. 撤销移除最后一条记录；“重置”清空全部记录并恢复初始状态；
10. 失败时不创建成功结果，不泄漏内部错误码。

## 8. 演进边界

如果后续需要严格按顺序执行多个模型编辑，应引入明确的编辑计划与中间结果编排，并重新设计任务展示和持久化；不能在当前单请求实现中静默模拟多轮模型编辑。
