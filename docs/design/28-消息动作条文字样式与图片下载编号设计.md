# 28 消息动作条文字样式与图片下载编号设计

> 状态：已实现（v2.1.42）。范围：助手/用户消息下方动作条的视觉形态、动作命名、图片消息的下载入口归属，以及多图批量下载的文件命名。

## 1. 范围

- 动作条由 28px 玻璃质感方形图标按钮改为「细线图标 + 文字」的无边框文本按钮条。
- 动作文案收敛为单词：引用、编辑、生图、重试、复制、下载。
- 图片消息不再显示文本答案的「下载回答」，下载统一由图片动作克隆按钮承担。
- 多图批量下载文件名共享同一时间戳并按转录顺序加 `-N` 序号。
- 非目标：不改变动作的绑定、可见性生命周期、意图路由或任何服务端契约。

## 2. 交互与状态

- 文本按钮条只在桌面端（`min-width:841px`）生效；移动端保持「更多操作」折叠交互。
- 文案来自按钮已有的 `title`，通过 `::after { content: attr(title) }` 渲染，因此模板与 JS 只维护一份 `title`/`aria-label`，不新增文案来源。
- 复制成功态：图标与「已复制」文字并排，2 秒后恢复；不改变 `copySuccessState` 的契约。
- 位置冻结：动作条与按钮在默认/hover/focus/active 全部状态下 `transform:none`，覆盖旧主题的 `translateY(-1px)` 行位移与按钮上浮、按压缩放。用户消息与带 `has-meta` 的助手消息都必须冻结（后者特异度更高，冻结选择器需同级或更高）。

## 3. 契约

- DOM 契约不变：`.msg-actions` 内按钮仍以 `copy-btn`、`refresh-btn`、`quote-btn`、`edit-btn`、`force-image-btn`、`download-answer-btn`、`mobile-more-btn` 类名标识，图片下载克隆仍带 `data-download-all-images` 与 `data-image-action-clone`。
- `bindMessageActions` 新增判定：`role === 'assistant'` 且消息内含 `img.generated-thumb` 时不绑定文本答案下载入口。
- 批量下载命名：`numberedDownloadFilename(index, total)` 返回 `<14位时间戳>[-N].png`；`total === 1` 时不加序号。整批共享同一时间戳，避免异步循环内逐张取时导致同名或乱序。
- 资源清单：`styles/message-actions-text.css` 是皮肤后功能覆盖层，必须登记在 `skin-system-integrity.test.js` 的 `POST_SKIN_CSS_ALLOWLIST`（契约见 27 号文档），并排在全部主题与皮肤样式之后，以保证覆盖优先级；根 `styles.css` 的 `stroke-width:2/2.25/2.45` 家族需要更高特异度选择器才能压过。

## 4. 安全

- 纯展示与命名层改动；不引入新的 payload、外部请求或存储字段。
- 文件名仅由时间戳与序号构成，不含用户输入，无需额外消毒。

## 5. 验收标准

1. 桌面端动作条显示为图标 + 单词文字，无边框、无投影、无磨砂底。
2. 鼠标移入消息或按钮时，动作条与按钮均不产生任何位移或缩放。
3. 点击复制后图标与「已复制」文字并排显示，不重叠。
4. 图片消息的动作条只有一个下载入口（`data-download-all-images`），无「下载回答」。
5. 多图下载得到 `...-1.png`、`...-2.png` 递增序号且共享同一时间戳；单图无序号。
6. 动作显隐生命周期（streaming / pending / ready）行为与改动前完全一致。

## 6. 回归测试

- `test/unit/image-batch-download-numbering.test.js`：多图编号与单图不加序号，并用可控 `timestampPrefix` 模拟跨秒验证整批共享同一时间戳（移除实现后必然失败：文件名全部相同或跨秒前缀不一致）。
- `test/unit/message-workflow-image-actions.test.js`：图片消息不再恢复文本答案下载入口。
- `test/unit/message-action-colors.test.js`、`message-actions-visibility.test.js`、`message-spacing-regression.test.js`：动作语义色、显隐生命周期与几何稳定性不变。
