# ChatUI v1.9.1

## Reliable chat completion and clarification

- Fixed completed streamed assistant messages disappearing from the page until refresh when a live DOM node retained stale pending-task ownership.
- Rebound streamed message nodes to their current display projection and synchronously cleared pending ownership at completion.
- Improved model-based clarification continuation so replies such as `2`, `第二张`, or `右边那只猫` can select one image while the assistant continues asking for a still-missing edit detail.
- Kept clarification interpretation model-driven, with strict partial-answer validation and one bounded model-contract repair instead of local keyword or ordinal routing.

## Identical source and image releases

- Added an exact runtime source fingerprint covering every application file copied into the Docker image.
- Added version, Git commit, source fingerprint, dirty-workspace state, and runtime mode to `/api/version`; the visible version now distinguishes dirty local workspaces.
- Made identified containers refuse startup when their actual runtime files differ from the source fingerprint supplied by CI.
- Added clean-worktree release previews and exact-image runtime verification for OCI revision labels, API identity, content-addressed bundles, and critical browser fixes.
- Changed Docker publication to build immutable candidates once, verify the candidate digest, and promote that same digest to `1.9.1`, `v1.9.1`, and `latest` in Docker Hub and Alibaba Cloud ACR without rebuilding.
- Required annotated release tags to belong to `main`, with release notes present in the tagged commit before publication.

## Verification

- Full project, architecture, syntax, unit, regression, and server smoke checks.
- Exact Docker runtime verification is required by main CI and the tag-triggered release workflow before version tags are promoted.
