# 14 图片预览压缩下载设计

## 范围与约束
- 预览新增独立压缩下载按钮；原图下载、复制、导航及持久化不变。
- 用户输入目标文件体积保留比例，不是宽高比例或编码质量。宽高和格式必须保持不变。
- PNG 无损重编码无法保证任意目标体积；JPEG/WebP 可搜索质量逼近目标，但不得承诺精确大小。
- 不支持原格式编码时明确提示，不偷偷转换格式。编码结果不比原图小时保留原文件，不填充无用字节凑体积。

## 流程与状态
打开预览不默认聚焦任何操作按钮。压缩操作快照当前图片和文件名 → 输入比例 → 读取 Blob → 解码 → 原尺寸 Canvas 编码 → 下载 → 释放临时资源。
重复点击在本次操作完成前忽略；取消不读图不下载。100% 直接下载原文件。目标比例无法保证，提示保留原格式和尺寸的限制。

## 契约与模块边界
- `client/app/image-preview-workflow.js` 编排预览和下载；DOM、Canvas 均仅在浏览器执行。
- 无新增 API、凭据、服务端状态或数据迁移。现有 manifest、静态公开路径、Docker COPY 范围保持兼容。
- 工具栏由主题控制；桌面 34px 按钮/8px 间距，移动端 30px 按钮/6px 间距。四个按钮共享视觉规则，键盘可聚焦。

## 安全与异常
- 使用既有图片来源，不附加认证请求头；文件名快照，不把来源或签名 URL 写入诊断。
- 对输出 MIME 校验，浏览器静默回退 PNG 视为不支持；用户获得可行动提示。
- 解码失败、空 Blob、编码异常均提示重试或原图下载；临时 URL 在成功和失败路径释放。

## 验收与回归门禁
- 专项测试实际调用压缩操作，验证原尺寸/PNG MIME、JPEG 目标体积搜索、100% 原文件、编码回退拒绝、取消、错误资源释放。
- 导航测试验证不默认选择关闭按钮；工具栏规则测试冻结间距和断点。
- 使用标准 runner，自动纳入 npm run check 和 main CI；容器资产由 Exact Docker runtime 验证。
