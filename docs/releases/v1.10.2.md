# ChatUI v1.10.2

本版本汇总并修正 1.10 系列的附件能力、更新日志体验和上传错误反馈。非图片附件使用 OpenAI Responses API 原生 `input_file.file_data` 发送；更新日志采用按版本折叠的 Markdown 阅读界面；文件校验与错误提示在前后端保持一致。

## 附件与文件输入

- 非图片附件保留为原始 Blob，在发送时编码为 Base64 Data URL，进入 `/v1/responses` 的 `input_file.file_data`。
- 不再调用 `/v1/files`，也不再依赖浏览器或服务端本地 Office/PDF/文本解析；历史附件仍可安全恢复。
- 支持 PDF、表格、文档、演示文稿以及文本和代码文件；PDF 支持 `auto`、`low`、`high` 三档 `detail`。
- 图片继续走多模态 `input_image` 和图片编辑链路；JPEG、PNG、WebP 尽量压缩，BMP 在浏览器支持时转换为 PNG。
- 原始附件 Blob 使用 IndexedDB 持久化；任务交给上游后从服务端内存快照移除 `file_data`。
- 单个文件和同一请求中的文件合计都必须严格小于 10 MB；服务端同步执行 Data URL、媒体类型、Base64 和解码大小校验。

## 上传错误反馈

- 超限或不支持的文件不会再短暂闪现后消失，而是在输入区显示红色错误卡片。
- 错误提示显示具体文件名和原因，例如“文件必须小于 10 MB”或“暂不支持该文件类型”。
- 错误卡片支持无障碍 `alert` 提示，并提供右上角圆形“×”按钮手动移除。
- 成功任务自动清理，失败任务会保留到用户关闭或重新选择文件。

## 更新日志阅读体验

- 版本日志使用独立版本卡片，最新版本默认展开，历史版本按需展开。
- 首次只挂载最新 12 个版本，可继续加载更早版本；展开后才渲染历史 Markdown。
- 宽表格和代码块在卡片内部滚动，不撑宽弹窗或页面；移动端底部弹层保留安全区并避免悬浮按钮遮挡。
- 继续使用共享 Markdown 渲染与安全净化链路。

## 清理与兼容性

- 移除旧的本地附件解析依赖、`/api/extract-file` 接口及对应 Docker 工具包。
- 上游必须支持 `/v1/responses` 的 `input_file.file_data`；文件最终可读性取决于上游 Endpoint 和模型能力。
- PDF 扫描页、图片和图表需要模型具备视觉输入能力；需要保留复杂版式时建议先转换为 PDF。
