# 07 测试与质量门禁

## 1. 测试分层

| 层 | 目录 | 内容 |
| --- | --- | --- |
| unit | `test/unit/` | 纯函数、模块、契约、状态机、错误分支、可注入依赖 |
| smoke | `test/smoke/` | 启动真实 HTTP server 的跨模块链路 |
| fixtures | `test/fixtures/` | 稳定、无秘密的输入 |
| （已移除） | `test/legacy/` | 已删除；历史回归必须迁移到 unit/smoke，不得恢复该目录 |

`test/run-tests.js` 是唯一标准测试入口。suite 必须导出非空命名 `test*` 函数数组。

## 2. 运行命令

```bash
npm run check                 # 项目 + 架构 + 语法 + 全部测试（单进程编排 scripts/check-all.js，测试自动并行分片）
npm test                      # 全部测试
npm test -- server-hardening  # 按路径/文件名片段聚焦
node test/run-tests.js unit/<name>.test.js
```

直接执行 suite 文件不经过 runner，不能作为测试证据。默认单项超时 10s。

全量测试由 runner 自动分片到多个 shard 进程并行执行（默认自适应，上限 6；`--jobs=<n>` 覆盖，`--serial` 或匹配文件少于 8 个时保持单进程）。开发过程只运行受影响的最小聚焦测试；`npm run check` 全量门禁只在提交代码与发版前各执行一次。

语法门禁以 `node --check` 为唯一裁决：进程内解析仅是快速路径，判定失败前必须经 `node --check` 复核（回归测试见 `project-tooling.test.js`）。

## 3. 命名与断言

- 测试名描述行为与期望，不描述实现细节。
- 优先调用真实导出并断言结果；源码字符串断言只用于必须冻结的装配/缓存/发布/兼容约束。
- 断言日志文件前必须 `await logger.flush()`。

## 4. 质量门禁（强制）

每个修复必须：

1. 为**该精确失败模式**写专属回归测试；
2. 证明它**在修复前失败**、**修复后通过**（先红后绿）；
3. 把测试接入 `npm run check` 与 CI。

没有对应质量门禁的修复视为未完成。涉及架构、缓存、发布或协议时，同时更新 `docs/design/` 与深文档。

## 5. 覆盖要求

- 核心链路必须有回归：静态/bundle 与缓存、路由与执行契约、任务生命周期与恢复、会话持久化、安全归属、日志脱敏、发布身份。
- 多会话并发恢复必须覆盖每会话独立 Job SSE：不同 session 必须各自建立一条 `/api/chat-jobs/:jobId/events` EventSource；同一会话/Job 的多个 waiter 共享一个 canonical aggregate，不重复建立连接；同一 terminal 只关闭自身连接。compact chat 帧不得携带 `id/status`，正文/思考之外的字段只允许一次 `ft`、终态 `done/e/rt` 或 offset 重置 `z`。
- 新增公共模块必须可被 Node 独立加载测试；浏览器 UI 行为优先抽纯逻辑测试。


## 6. 插件回归

`test/unit/plugins.test.js` 固化：配置失败关闭、HTTP 参数/query/凭据隔离、MCP 初始化与工具白名单、浏览器 managed Job 协议、面板审批锁定、Responses 传输拒绝，以及 manifest/聊天分支装配。未选择插件时的既有 chat workflow 测试是默认行为回归，禁止删除或放宽。

## 7. 入站 MCP 回归

入站 MCP 的专属门禁是 `test/unit/mcp-usage.test.js`，覆盖仅 header token 认证、`X-API-Key`、body/query token 拒绝、CORS 与 `no-store`、JSON-RPC 生命周期、10 个工具、按用户名和部门名查询、无部门密码的部门统计、XLSX embedded resource、反馈审核顺序和日志/结果脱敏。`test/unit/usage-data-layer.test.js` 另外覆盖 `validateKey(apiKey)` 的模型列表、缓存和上游失败映射，以及按用户名和部门名查询的参数绑定与聚合结果；`test/unit/api-contract.test.js` 保证浏览器反馈在抽取共享 `feedback.service` 后契约不变。聚焦命令为：

```bash
npm test -- mcp-usage usage-data-layer api-contract feedback-review
```
