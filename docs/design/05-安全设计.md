# 05 安全设计

## 1. 身份与任务归属

- `request-principal` 为每个浏览器颁发 HMAC 签名 principal cookie：HttpOnly、SameSite=Strict、可选 Secure、可轮换。
- principal 派生 owner key，chat/image/image-batch 任务按 owner 隔离；非本人任务与不存在任务同样返回 404，避免泄露存在性。
- 颁发/刷新 cookie 的响应强制 `private, no-store`；已持有 cookie 的请求不覆盖业务缓存语义。

## 2. 代理与 URL 策略

- 上游转发只允许白名单方法与路径；重定向与目标 URL 经 `server/security/url-policy.js` 校验，禁止 SSRF 与任意内部地址。
- 代理请求头经 `server/proxy/headers.js` 处理，不把宿主头或不受信头透传给上游。

## 3. 内容安全（浏览器渲染）

- 所有 Markdown 输出必须经 DOMPurify + 消毒策略 + 链接策略；源规范化、mermaid 规范化在渲染前执行。
- CSP 默认 `default-src 'self'`，脚本只允许 self/受信 CDN/inline/blob，样式与字体同策略；图片与连接按需放宽。
- 上传附件按文件类型、大小、数量限制（`shared/file-inputs.js`），上传与展示路径使用受限 URL。

## 4. 密钥与配置

- 私密配置放根目录 `.env.local`（Git 忽略）：只补缺，不覆盖部署环境变量；禁止强制提交。
- 主要密钥：`CHATUI_PRINCIPAL_SECRET`、数据库连接、DingTalk 反馈凭据。所有敏感值只从环境读取。
- `config/public.json` 只放非敏感 UI/feature 配置；服务端数据、SQL、凭据禁止进入静态公开目录或 `shared/`。

## 5. 日志与脱敏

- API Key、Authorization、自定义敏感 Header、文件/图片 Base64、签名 URL 查询参数不写入日志。
- 系统提示词只记录长度与哈希；reasoning 只记录长度；业务正文如需追踪受控落盘，且禁止提交 Git 或附到 Release。
- 意图可见轨迹只允许结构化阶段摘要、证据标识和稳定 reason code；不得展示或持久化原始私有思维链、完整模型输出、凭据或二进制内容。
- 日志 writer 有界异步：队列达到上限显式 drop，不阻塞请求、不无限占内存。

## 6. 输入校验

- 路由、幂等、能力契约由 `server/validators/` 集中校验；handler 内不得复制校验逻辑。
- 请求体大小与心跳 payload 大小有上限，超限返回 4xx。

## 7. 上线安全评审清单

- [ ] 无硬编码密钥、无 `.env`/日志提交
- [ ] 新端点有 principal 归属或明确的公开性判断
- [ ] 新渲染路径过消毒与链接策略
- [ ] 新上游路径进白名单且有 URL 校验
- [ ] 敏感字段已脱敏并有回归测试
