# 20 图片编辑记录编辑与删除设计

> 状态：设计基线，已进入实现。
> 日期：2026-09-12
> 关联文档：`16-图片编辑工具设计.md`、`19-图片编辑混合操作设计.md`、`04-API与服务契约设计.md`

## 1. 范围与目标

图片编辑工作台已把评论、局部擦除、移除背景和提升清晰度统一为“修改记录”。本次允许用户直接管理这些记录：

- 评论文字可原位编辑，保留原评论的坐标、颜色和画布标记；
- 评论可删除，删除后剩余评论按当前顺序重新编号为连续的 1、2、3…；
- 局部擦除可删除，删除时同时移除该记录对应的叠层笔迹和 mask 选区；
- 移除背景和提升清晰度可删除，删除后同步关闭对应全局操作；
- 删除任一记录后，最终用户消息、模型提示词、生成 mask 和全局参数都必须与右侧剩余记录保持一致。

移除背景记录可以与其他记录同时存在于编辑器中，但提交时必须遵循 19 的模型能力约束：移除背景只能单独执行；删除其他记录后，单独保留移除背景即可恢复提交。

非目标：

- 不允许编辑“移除背景”“提升清晰度”全局操作，但允许删除；
- 不提供局部擦除说明编辑；擦除只增加逐条删除能力；
- 不改变历史记录的执行顺序和一次 `edit_image` 请求模型；
- 不新增服务端接口、持久化字段或任务类型；
- 不提供任意调整评论坐标或擦除笔迹的能力。

## 2. 流程与状态

```text
修改记录卡片
  -> 评论：编辑文字 / 删除
  -> 局部擦除：删除
  -> 移除背景 / 提升清晰度：删除
      -> 评论编辑保存：更新原 action，不改变坐标、颜色或笔迹
      -> 删除：移除 action 及对应评论/笔迹/全局开关
      -> 评论集合重新按剩余顺序枚举编号
      -> 重绘画布标记、修改记录列表和按钮可用状态
  -> 完成并应用
      -> 使用剩余记录重新生成 mask、用户消息和模型提示词
```

编辑器新增内存状态：

```text
{
  recordSeq,
  editingRecordId,
  editingRecordSize,
  history: [
    { id, type: 'comment', comment: { x, y, text, color, thumbnail } },
    { id, type: 'erase', instruction, strokes: [], thumbnail },
    { id, type: 'operation', operation: 'remove_background' | 'enhance' }
  ]
}
```

- 评论编号只由当前 `history` 中剩余的评论声明顺序决定，不保存永久序号；
- 删除任意记录不改变其他记录在 `history` 中的相对顺序；
- 编辑记录只替换评论文字，不复制记录，不改变记录位置；
- 空评论的保存必须失败关闭并保留编辑态。

## 3. UI 与交互契约

- 评论卡片右上角提供“编辑”“删除”两个图标按钮；局部擦除和全局操作卡片只提供“删除”按钮；
- 评论正文使用常规字重，不加粗，与编辑框中的文字观感一致；
- 编辑评论时在卡片原位显示多行文本编辑框，编辑框与原文字块同宽同高（进入编辑前先量原文字块尺寸），不改变卡片宽度；编辑期间 Enter 换行，Ctrl/Cmd+Enter 或“保存”提交，Escape 取消；保存后继续使用原评论颜色和画布位置；
- 评论卡和擦除卡必须在右侧展示对应图片局部 PNG 截图：截图为图片短边 15% 的固定 4:3 小窗口，评论以标记点为中心、擦除以该记录笔迹的中心为中心，不随笔迹边界放大取样区域；
- 删除评论后，画布编号、卡片编号、用户消息编号和模型提示词编号同时重新计算；
- 删除擦除后，右侧记录和画布红色笔迹立即移除，下一次应用不再包含该笔迹的 mask 和说明；
- 删除移除背景或提升清晰度后，对应工具按钮恢复未选中状态，提交时不再携带该步骤或 `background` / `output_format` 参数；
- 全局操作也可以通过工具栏再次点击取消；工具栏取消和右侧删除共同更新同一份 `history`，两条路径不得产生重复记录；
- 删除操作不进入“重做”历史；现有“撤销”只按 `history` 尾部继续回退；
- 编辑期间按 Escape 取消编辑，不提交任何修改。

## 4. 数据与执行契约

- 不改变 `operation=edit_image`、`api=image_edit` 及 dispatch contract 协议；
- 提交时从剩余评论动作构建 `comments`，从剩余擦除动作构建 `eraseActions`；
- mask 由剩余评论圆和剩余擦除笔迹合并生成；
- 评论提示词按剩余评论数组重新编号，编号必须从 1 连续递增；
- 用户消息按剩余记录重新生成，不保留已删除记录的文字；
- 编辑评论文字只影响提示词，不影响评论坐标或擦除笔迹；
- 局部截图只在编辑器内存中生成，不新增持久化或网络字段；删除/编辑记录不改变已有截图；
- 删除全局操作只影响对应 operation，其他记录顺序和参数保持不变。

## 5. 安全与错误边界

- 编辑内容沿用现有文本渲染与转义边界，不新增 HTML 注入路径；
- 保存前对评论执行 `trim`，空内容不产生记录变更；
- 不新增网络请求，不记录用户编辑文字以外的内部状态；
- 删除任意记录后，画布、记录列表、mask 和提示词必须来自同一份剩余记录状态。

## 6. 验收标准

1. 评论记录可编辑文字，保存后卡片、用户消息和模型提示词同步更新；
2. 评论记录可删除，删除后剩余评论在画布、卡片和提示词中连续重编号；
3. 擦除记录只显示删除按钮，不提供编辑按钮；
4. 擦除记录可删除，删除后对应笔迹、mask 和提示词内容同时消失；
5. 全局“移除背景”“提升清晰度”记录只显示删除按钮，不显示编辑按钮；删除后工具状态和最终请求参数同步更新；
6. 删除后再次“完成并应用”，仅提交剩余记录；
7. 空评论不能保存；
8. 原有撤销、重做、清空和混合操作行为不回归。
9. 评论正文不加粗；评论编辑框为多行文本，且宽度、高度与原文字块一致；评论和擦除记录在右侧展示对应局部截图；修改记录面板明显宽于左侧工具栏。

## 8. 演进边界

如果后续允许调整评论坐标、拆分擦除笔迹或编辑全局操作，应扩展记录模型和编辑器交互，而不是在渲染层特殊处理；任何新增操作仍必须进入同一条预览、mask、提示词和提交链路。
