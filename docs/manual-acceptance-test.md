# ChatUI 全平台手工验收测试用例

> 最后整理：2026-08-15
> 测试范围：当前 ChatUI 仓库中用户可见的全部核心功能，以及关键异常、恢复、兼容和安全场景。  
> 默认测试地址：`http://127.0.0.1:8765`（本项目本地服务固定使用 8765 端口）。  
> 本文不绑定固定版本；每次执行前必须访问 `/api/version`，记录实际版本、Git SHA、源码指纹和工作区模式。

## 0. 应用定位与验收目标

ChatUI 的定位不是通用企业协作平台，而是一个**轻量、可直接部署、面向 OpenAI 兼容服务的聊天与图片工作台**。因此本验收以以下产品承诺为主线：

1. **接入简单**：单页前端与 Node.js 代理可在固定端口 `8765` 直接运行，核心浏览器依赖随应用本地交付。
2. **兼容可靠**：可接入第三方网关、私有兼容服务、聚合 API 或本地模型代理，并正确处理流式、非流式、图片和文件响应。
3. **意图准确**：普通聊天、文件问答、看图、图片对比、OCR、文生图、参考图生成和图片编辑不能互相串路由。
4. **资源可信**：当前上传、引用消息、历史图片和历史文件必须使用稳定身份与明确角色绑定；不允许猜错目标后继续执行。
5. **过程可恢复**：聊天和图片 Job 在刷新、切会话、SSE 中断和停止后保持一致，不丢可见结果、不重复写入、不跨会话串线。
6. **本地优先且安全**：会话与媒体主要保存在浏览器本地；API Key、附件正文、图片二进制和内部执行协议不得出现在不必要的日志、路由请求或导出文件中。
7. **富内容可用**：Markdown、代码、公式、Mermaid、HTML 预览、图片预览/下载/复制和 Office/PDF 原生文件输入可稳定工作。

“覆盖全”在本文中指：覆盖当前仓库公开的用户功能、核心协议、恢复链路、异常边界、安全边界、响应式与部署运行；不把上游模型自身的文案风格、事实正确率或生成图片的审美一致性当作 ChatUI 缺陷，除非固定标记、请求合同、资源绑定或操作类型错误。

## 1. 使用说明

### 1.1 状态定义

- `PASS`：实际结果与预期一致，且证据齐全。
- `FAIL`：实际结果与预期不一致；必须记录缺陷编号。
- `BLOCKED`：环境或前置问题阻断了本应执行的用例；不能当作通过。
- `SKIP`：仅用于明确标注“环境依赖/上游能力依赖”的用例，且当前环境确实未提供该能力。
- `NOT RUN`：尚未执行。

每条用例执行后填写：

```text
状态：PASS / FAIL / BLOCKED / SKIP / NOT RUN
实际结果：
证据：截图/录屏、浏览器控制台、Network 请求、下载文件、缺陷编号
执行人：
执行时间：
```

### 1.2 优先级

- `P0`：发布阻断；任一失败都不能验收。
- `P1`：主要功能或重要恢复路径；失败原则上不能发布。
- `P2`：增强体验、兼容性或特定环境能力；需评估后决定。

### 1.3 验收标准

1. 所有适用于当前环境的 `P0` 用例必须 `PASS`。
2. 所有适用于当前环境的 `P1` 用例必须 `PASS`；若例外放行，必须有缺陷、影响说明和负责人。
3. `SKIP` 必须写明缺失的模型、数据库、浏览器能力或故障注入条件。
4. 不允许出现：跨会话串消息、刷新丢失已显示输出、错误图片/文件被执行、API Key 泄漏、历史顺序错乱、停止后任务继续写入。
5. 浏览器控制台不得出现未解释的应用异常；Network 中不得向第三方泄漏 API Key 或本地附件正文。

### 1.4 单条用例固定字段

本文每条正式用例都固定包含以下四项，不能省略：

- **前置条件**：执行前必须具备的服务、数据、浏览器状态、模型能力或前序结果。
- **输入 / 操作**：人工输入的文本、文件、配置值、接口请求，以及必须执行的点击、键盘、刷新或故障注入动作。
- **应该输出**：界面、Network、下载文件、持久化状态或服务端应产生的可观察结果。
- **评判依据**：明确的 PASS/FAIL 判定方法及必须保留的证据。只要“应该输出”任一关键项不满足，即判为 FAIL；环境确实缺失且用例标记“环境依赖”时才可 SKIP。

对于生成式模型的开放输出，不按措辞或像素完全一致判定；按任务完成度、固定标记、资源绑定、接口类型、上下文隔离和安全边界判定。

## 3. 覆盖矩阵与建议执行顺序

### 3.1 建议执行顺序

1. 启动与配置：BAS → CFG。
2. 会话、输入与聊天：SES → CMP → CHT。
3. 重点恢复回归：REC（尤其 REC-001、REC-002）。
4. 思考与路由：RSN → RTE。
5. 图片与附件：IMG → ATT。
6. 渲染、持久化、备份：RND → PST。
7. 公告、版本、统计、反馈：INF → USG → FBK。
8. 移动端、可访问性、服务端异常与安全：UX → ERR。

### 3.2 应用定位驱动的覆盖矩阵

| 覆盖域 | 主要风险 | 用例范围 |
|---|---|---|
| 启动、静态资源与运行身份 | 白屏、资源缺失、版本错配、固定端口失守 | BAS、DEP |
