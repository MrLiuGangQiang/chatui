# ChatUI v2.1.8

ChatUI v2.1.8 加固意图路由提示词的字段契约与语义边界，减少弱路由模型下的资源绑定丢失与 operation 误判。

## 改进

- 意图路由提示词明确 `resource_refs` 每项仅含 `candidate_key` 与 `role` 两个字段，`candidate_key` 必须取自 `resource_candidates` 原值，禁止模型自造 `message_index`/`ref`/`key` 等字段，避免资源绑定丢失。
- 明确“这个描述/上述”等回指属于对 quoted 消息的明确指向，goal 使用其正文事实时必须绑定对应消息的 `context` 角色。
- 明确“仅文件无图是 file_qa”，避免把“文件 + 后续生成图片”误判为 `multimodal_qa`。
- 意图语义审查节点显式枚举 7 个 reason code，减少非法 code 被兜底归一化而丢失真实错误信号。
- 图片执行指令书写节点显式声明 `status` 仅 `ready` / `needs_clarification` 两个取值。
- 多图任务规划节点区分结构上限 50 与执行批次上限 5，规划节点只按用户要求拆分、不自行截断。

## 稳定性与质量

- 新增回归测试覆盖 `resource_refs` 字段契约、quoted 指代绑定、文件/多模态边界、critic reason code、图片指令 status 与图片规划上限。
- 提示词长度门禁保持：完整/复杂 ≤7400、简单 ≤4400。
- `npm run check` 全量通过（1836 个测试，316 个套件）。
