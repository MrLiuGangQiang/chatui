# 16 图片编辑工具设计

> 状态：一期（擦除 / 移除背景）、二期（评论）、清晰度提升与混合操作（见 19）已实现；调整尺寸已按 21 重新接入图片编辑工作台。三期（多轮编辑）在本文档后续补充。图片编辑入口为图片右上角常驻“编辑”按钮，点击直接打开单层图片编辑器（工具、画布与评论/选区操作在同一界面）。
> 日期：2026-09-11

## 1. 范围与目标

对齐 ChatGPT 图片编辑工具栏的产品形态，在聊天中的图片消息上提供就地编辑能力，复用现有 `edit_image` + mask + 参数透传链路，不新开服务端接口。

一期（本文档范围为验收基线）：

- 擦除：在图片上涂抹选区，生成 alpha mask，按 `image + mask + prompt` 调用图片编辑；
- 移除背景：一键编辑，`background=transparent` + `output_format=png`（当前产品实现固定输出 PNG；上游 API 的 WebP 能力不在本期契约内）；
- 画质提升：一键编辑，不创建 mask，要求增强细节、纹理、边缘和局部对比度，同时保持构图、主体、颜色、光照、风格和文字内容不变；
- 调整尺寸：通过“调整尺寸”菜单选择方形 1:1、竖版 3:4、故事版 9:16、横版 4:3 或宽屏 16:9，加入一条尺寸记录并复用 `edit_image` 的 `size` 参数；详见 21。

二期（已实现）：评论（编号评论点转编辑指令；发送时使用干净原图 + 评论位置生成的编辑 mask + 坐标提示词，不把编号标记画进原图）。

三期：对齐 ChatGPT 多轮编辑体验（Responses API `image_generation` 工具、`action=edit`、`input_image_mask`、`previous_response_id`）。

非目标：

- 不做图层、蒙版布尔、专业修图能力；
- 不引入服务端图片存储、新 HTTP 接口或数据库；
- 不改变普通聊天/生图的意图路由语义：编辑器发起的编辑是确定性操作，不经过意图模型。

## 2. 官方能力依据

OpenAI 官方文档（developers.openai.com）：

- Image generation 指南（`/api/docs/guides/image-generation`）：edits 端点支持编辑已有图片、多图参考、`image + mask` 局部编辑；
- Images edit API（`/api/reference/resources/images/methods/edit`）：`mask`、`input_fidelity`、`background`、`size`、`quality`、`output_format`、`output_compression` 参数；
- mask 要求：与源图同格式同尺寸、小于 50MB、必须含 alpha 通道；多图输入时 mask 只作用于第一张；
- GPT Image 的 mask 是 prompt-based 指导，模型可能不严格遵循精确保形状，因此提示词必须描述编辑意图；
- 透明背景仅支持 `png`/`webp` 输出；
- 自定义尺寸：宽高为 16 的倍数、比例 1:3 至 3:1、单边不超过 3840、总像素 655,360 至 8,294,400；
- ChatGPT 图片生成/编辑指南（learn.chatgpt.com/docs/image-generation）：选中图片打开 expanded viewer；在 Canvas view 用 Comment 给一张或多张图片添加精确反馈；可选中图片的具体区域并描述修改；描述要改什么、保留什么。

## 3. 流程与状态

```text
图片消息（assistant / user 图片）
  -> 图片右上角常驻"编辑"按钮
      -> 点击直接打开单层图片编辑器（暗色背景 + 大图 + 工具条）
          -> 编辑器内切换：评论 / 移除背景 / 画质提升 / 擦除
              |- 评论：鼠标变为评论光标；点击图片放置编号标记并弹出内联输入；可连续评论多处
              |- 擦除/选区：涂抹区域，可填写"改成什么"，留空则移除并自然填充
              |- 移除背景：无需画布操作，直接提交
              |- 画质提升：无需画布操作，直接提交
          -> 评论模式：可连续标记多条评论；点击"应用"把编号评论列表作为用户消息提交
          -> 擦除/移除背景：点击"应用"提交
              -> 构造确定性 edit_image 请求（干净原图 + mask + prompt）
              -> 现有图片任务通道执行（loading / 取消 / 失败提示复用）
          -> 取消 / Escape / 点击背景空白：关闭编辑器，不提交
  -> 结果写入新的 assistant 图片消息，可继续引用编辑
```

编辑器状态（内存，关闭即释放）：

```text
{ imageBlob, width, height, tool, brushSize, strokes[], comments[], maskBlob? }
```

## 4. 数据与契约

mask 生成规则：

- 与源图同宽高；PNG；带 alpha 通道；
- 涂抹覆盖区域为透明像素（待编辑区域），其余为不透明白色（保持区域），符合 OpenAI mask 语义。
- 评论 mask：与源图同宽高，每个评论位置生成透明圆（待编辑区域），其余为不透明白色（保持区域）。

编辑请求：

- `operation=edit_image`，`api=image_edit`；
- bindings：`target` 图片（source 取原图来源）+ `mask` 图片（role=mask，最多 1 张，服务端已有约束）；
- arguments：`prompt`，可选 `size` / `background` / `output_format` / `quality` / `input_fidelity`；
- 提示词：
  - 擦除（未填写描述）：`Remove the selected area and fill it naturally with the surrounding background.`；
  - 擦除（填写描述）：固定为“请只修改图片中编辑蒙版覆盖的区域。\n修改内容：<用户描述>\n蒙版外的原始内容必须保持不变，不要输出蒙版、编号或任何标记。”，避免重复“修改选区”前缀并明确编辑边界；
  - 移除背景：`移除此图像的背景。保持所有前景主体不变且完整无损，边缘干净平滑。将背景设为透明。`；
  - 画质提升：`提升这张图片的清晰度。增强细节、纹理、边缘和局部对比度，减少模糊、噪点与压缩伪影；保持原始构图、主体、姿态、颜色、光照、风格和文字内容不变，不要添加或删除任何元素。`
  - 评论：动态生成，先说明蒙版透明区域才允许修改、结果不得保留编号，再按 `序号. 位置 (x=…, y=…)：评论内容` 列出每条评论。

尺寸策略（`shared/image-size-policy.js`，浏览器与能力注册表共用）：

- 预置：`auto`、`1024x1024`、`1536x1024`、`1024x1536`；
- 自定义：宽高为 16 的倍数、比例 1:3 至 3:1、单边 ≤3840、总像素 655,360 至 8,294,400；
- 校验失败返回可操作中文提示，不静默截断；
- 该策略继续服务生成/路由参数；编辑器尺寸记录通过 `allowFixedOverride` 产生一次显式 `size` override，且不改变设置页的生成默认值。

参数通道：

- `edit_image` 的参数 schema 允许编辑器传入显式尺寸选择；尺寸值必须通过同一策略校验；
- 生成路径（`text_to_image` 等）保持原不变量：尺寸只由设置页决定，文本解析、模型输出与澄清都不会改变它；
- 移除背景通过 override 传 `background=transparent` 与 `output_format=png`。

## 5. 前端行为

- 图片右上角常驻小尺寸彩色"铅笔 + 波浪线"编辑圆钮（距图片右上角 6px、无 hover 依赖；26px 圆形磨砂玻璃（无边框）：半透明白底 + backdrop blur + 柔和投影，叠加青→蓝→紫→粉渐变笔迹，保证在图片上清晰可见），点击直接打开单层图片编辑器；普通文本消息与不可恢复图片不显示入口；
- 多图消息中的每一张生成图各自拥有独立编辑入口，点击只打开该图片；批次/多图结果返回时必须与单图、聊天、异常和澄清共用 `reconcileMessageActions` 这一套消息操作生命周期：用户消息发送后立即进入 `ready`，assistant 等待/流式/未完成保持 `pending`，成功、异常、澄清、停止后统一切换为 `ready`；`data-persist`、`data-streaming`、job 等属性只描述执行/持久化元数据，不得再单独决定按钮显隐。完成时补齐引用、下载全部图片与重新生成，随后才补图片专属操作；不得依赖刷新页面才出现；
- 全屏图片预览的右上角提供编辑按钮，与下载 / 复制 / 关闭使用同一套圆形操作按钮样式（`.image-preview-action`：同尺寸、同半透明底、同 hover、白色图标），仅图标为铅笔 + 波浪线；复用消息图片的按钮工厂（预览变体）与打开流程，不重复实现，点击后关闭预览并进入单层编辑器；
- 编辑器铺满整个视口（类似图片预览）：深色画布区、尽可能大的图片、工具条与操作在同一界面；不在消息正文插入工具条，也不再叠加第二个工具弹层；Escape 或点击背景空白关闭；仅当图片可恢复为 Blob 时工具可用；
- 生成图缩略图与用户附件预览统一使用 2px 小圆角，不再跟随消息气泡的大圆角；移除背景的结果强制输出 PNG，聊天缩略图不得再绘制棋盘格，透明区域直接透出消息背景，下载文件名强制为 .png；
- 编辑器匹配所有生成图（渲染时临时 blob/data 源属性会被剥离，不能依赖 data-persisted-src）；图片来源在使用时按 persistedSrc → originalSrc → persistedUrl → objectUrl → currentSrc → src 回退解析；
- 消息区使用 MutationObserver 兜底：懒渲染、历史恢复或属性更新后出现的图片同样会获得常驻编辑入口；
- 编辑器支持混合操作：评论 / 擦除为可累计的局部记录，移除背景 / 画质提升为各最多一条的全局记录；点击"应用"把全部记录合并为一次 edit_image 请求，取消 / 关闭不提交；
- “移除背景”和“画质提升”工具栏按钮为开关：首次点击添加记录，再次点击取消并从右侧操作历史中移除；
- “移除背景”必须单独提交；与评论、擦除或画质提升同时存在时，点击“应用”只提示用户单独使用移除背景，不创建图片任务；
- 编辑器默认不预选破坏性工具；擦除/选区从笔迹计算归一化中心、边界和画面方位，模型提示词按“可编辑蒙版 + 选中区域位置 + 修改内容 + 蒙版外保持不变”的结构生成，留空时按移除并自然填充处理；画质提升不创建 mask，不提供参数输入；
- 编辑器为无顶部标题栏的模态工作台：左侧工具栏提供评论 / 移除背景 / 画质提升 / 擦除，擦除模式显示画笔与选区修改说明输入；底部保留撤销、重置、清空及带图标的“应用 / 取消”；不再提供缩放、适应窗口、原始尺寸或全屏控件；
- “撤销”按操作历史逐步回退：涂抹按一次完整手势记录（一次拖拽只算一步），评论按确认顺序记录；“重置”定义为清空所有涂抹、评论和全局操作记录，重置画笔及输入并回到中立初始状态，不恢复已撤销内容；Ctrl/Cmd+Y 与 Ctrl/Cmd+Shift+Z 不执行破坏性重置；
- 编辑器在打开时立即完成工具初始化（图片解码前即可交互）；评论使用与标记同一水平线对齐的悬浮输入：点击评论后鼠标变为瞄准镜光标（热点为图标中心，落点即标记位置）；点击图片放置标记后自动聚焦输入框，可直接输入；回车或蓝色圆形"✓"按钮确认、"×"取消；点击放置时即从随机多色色板确定该条评论颜色，并同步用于待确认标记、确认按钮和确认后的 1、2、3… 小号编号标记（较细白色描边 + 白色数字，水平/垂直精确居中，带轻微投影）；画布标记与右侧评论序号共用该颜色，可连续评论多处；点击编辑器"应用"把编号评论列表作为用户消息提交；发送时始终使用干净原图作为 target，并根据评论位置生成编辑 mask + 坐标提示词；评论与擦除单条说明最多 1000 个字符，最终编辑提示词最多 4000 个字符，超限必须明确拒绝而不能静默截断；模型只修改 mask 允许的区域；
- 浏览器实测覆盖：常驻编辑入口直接打开无标题栏单层编辑器、中性初始状态、评论编号与多处评论发送、选区修改说明、擦除 mask、移除背景参数和画质提升链路，并覆盖窄屏竖图不裁切； 窄屏底部操作按钮采用两行自适应布局，不产生横向溢出。
- 每次编辑先产生一条用户消息（如"移除图片背景"、"1. <评论>\n2. <评论>"、用户填写的局部修改说明），随后插入 assistant 结果；用户消息与结果都即时出现并持久化，不依赖刷新；
- 提交复用现有图片任务生命周期（`sendImage` 通道、mask 附件参数、任务状态与取消），不新增服务端接口；
- 编辑器发起的编辑与聊天发起的图片任务共用同一套任务状态机：编辑期间会话为运行中（发送按钮显示停止），结果提交或失败后必须 settle 并释放 active run，防止焦点/会话恢复把会话标忙后无法解除；
- 图片结果提交后任务状态机必须收口为终态：即使生命周期只观察到 HANDOFF（handoff 事件晚于结果提交），已提交的 `JOB_COMPLETED_COMMITTED` 也要把任务置为完成；多图恢复完成后必须 settle 任务（completed/failed），不能只清理 resume 标记；发送按钮不得停留在"停止/进行中"；
- 上游不支持 mask / transparent 等能力时，失败文案为中文可操作提示，内部错误只进日志。

## 6. 安全与隐私

- 原图与 mask 仅存在于内存与既有附件缓存（IndexedDB），不写入会话正文；
- 图片 base64 / mask 数据禁止进入日志（沿用 `image-edit-payload.service` 的脱敏与 multipart 组装）；
- 自定义尺寸严格校验，防止超大画布造成内存问题；
- 编辑器不新增网络调用，仅在用户点击"应用"后走既有图片请求。

## 7. 验收标准

1. 图片右上角常驻小尺寸"铅笔 + 波浪线"编辑圆钮（26px，距图片右上角 6px）；多图消息中每张图片各有独立入口；点击直接打开单层编辑器（工具条、画布与修改说明在同一界面），消息正文不插入工具条，也不会叠加第二个工具弹层；关闭按钮 / Escape / 点击背景可退出；普通文本消息、不可恢复图片不显示入口；
2. 擦除：涂抹后可生成与源图同尺寸、含 alpha 的 mask，并成功提交一次 `edit_image`，结果作为新的图片消息返回；
3. 移除背景：必须作为唯一操作一键提交，请求带 `background=transparent` 与 `output_format=png`；与其他操作混用时不提交并明确提示。结果保持透明 PNG，聊天缩略图不绘制棋盘格，下载文件为 .png；
4. 评论：点击图片放置编号标记并弹出内联输入；可连续评论多处；点击编辑器"应用"把编号评论列表作为用户消息提交，并执行一次 edit_image；target 为干净原图 + 评论位置生成的 mask + 坐标提示词；不发送带标记的合成图，只修改 mask 允许的区域；
5. 上游不支持的场景显示中文可操作提示，不暴露内部诊断信息；
6. 普通聊天、生图与既有图片编辑路径不回归。
7. 生成图缩略图（含用户附件预览）圆角为 2px，且 CSS bundle 中生成图相关圆角声明不得大于 2px。
8. 编辑器默认不预选破坏性工具；擦除/选区可填写修改说明并进入 edit_image 提示词，留空时保持移除并自然填充语义。
9. 编辑器顶栏为居中工具栏且三项工具均带图标；底部右侧依次为带图标的"应用/取消"；评论光标热点与落点一致，点击图片后评论输入框自动聚焦可立即输入。
10. 全屏图片预览右上角显示与消息图片一致的编辑圆钮；点击复用同一编辑入口与打开流程，关闭预览并进入编辑器。

## 10. 二期：评论

> 状态：二期（评论）已实现并通过 `npm run check`；一期（擦除 / 移除背景）和调整尺寸（见 21）已上线。

### 10.1 范围与目标

- 评论（Comment）：在图片上放置编号评论点并关联文字，把"编号 -> 文字 + 归一化坐标"写入提示词，并按评论位置生成编辑 mask；
- 与一期一致：用户在编辑器中的选择是确定性的，直接编译 `edit_image`，不经过意图模型；
- 不新增服务端接口：评论走既有 `edits` 上传通道（干净原图 + mask）。

非目标：

- 不做矢量图层编辑、吸附对齐、多人协作评论；
- 不引入评论持久化（关闭编辑器即释放），评论只作为本次编辑的提示词来源；
- 不提供标注/画笔/箭头/矩形/文字工具。

### 10.2 流程与状态

```text
图片 -> 编辑 -> 选择"评论"
  鼠标变为评论光标 -> 点击图片放置编号标记并弹出内联输入
  -> 输入评论 -> 回车或"✓"确认（"×"取消）
  -> 可继续点击图片评论多处 -> 标记按 1、2、3… 编号
  -> 点击编辑器"应用"发送
  -> 根据评论位置生成编辑 mask（target 仍是干净原图） -> prompt = "图片上有一个编辑蒙版…1. 位置 (x, y)：<文字>"
  -> 用户消息 = 编号列表（1. <文字>\n2. <文字>）
  -> edit_image(target=干净原图, mask=评论位置生成的 mask, prompt)
```

编辑器状态扩展：

```text
{ comments: [], pendingComment: null }
```

### 10.3 契约

- `edit.mode = 'comment'`；
- 输入图：target 为干净原图；`edit.maskBlob` 为评论位置生成的编辑 mask（透明区域=可修改，其余保持不变）；
- 提示词：说明"图片上有一个编辑蒙版，透明区域允许修改，其余区域保持不变"，并按编号列出每个位置的归一化坐标 (x, y) 与修改内容；
- 用户消息：编号列表（`1. <文字>` 换行 `2. <文字>`），由 `edit.label` 传入；
- 携带 1 张 mask（role=mask）；bindings 为 target + mask，target 始终是干净原图；
- 评论点为归一化坐标；生成 mask 时按原图分辨率把每个评论点渲染为透明圆，与显示尺寸解耦。

### 10.4 安全与隐私

- 评论只在本地画布生成 mask，不新增网络请求；
- 评论文字与指令长度受限（编辑器侧截断），不进入日志；
- 干净原图与评论 mask 沿用一期的图片附件链路与脱敏规则。

### 10.5 验收标准

1. 评论光标点击图片放置编号标记并弹出内联输入；确认后标记按 1、2、3… 编号；
2. 可连续评论多处；点击编辑器"应用"发送；
3. 应用把编号评论列表作为用户消息提交，并以干净原图 + 评论 mask 执行一次 `edit_image`（携带 1 张 mask）；提示词包含编号、归一化坐标与修改内容。
4. 失败场景显示中文可操作提示，不暴露内部诊断。

## 11. 三期：Responses 多轮编辑

> 状态：服务端通道已实现并通过 `npm run check`（默认关闭，不改变现有部署）；客户端会话串联（transport 选择与 previous_response_id 传递）待实现。

### 11.1 范围与目标

- 为图片编辑提供第二传输：Responses API 的 `image_generation` 工具（`action=edit`、`input_image_mask`、`previous_response_id`），对齐 ChatGPT 的多轮高保真编辑；
- 默认关闭：只有部署方显式配置后才启用；生成路径永不受影响；
- 不改变 `dispatch_contract.v1`：契约仍是 `image_edit`，传输选择发生在服务端执行层。

### 11.2 启用方式

- 部署级：`CHATUI_IMAGE_EDIT_TRANSPORT=responses`（`server/config/index.js`）；
- 请求级：图片任务 body 的 `transport` 字段可覆盖（客户端尚未发送，供后续会话串联使用）；
- 前置条件：上游必须实现 Responses API 的 `image_generation` 工具，否则启用后请求会失败；失败保持诚实报错，不回退到 Image API，避免静默改变语义。

### 11.3 契约

请求（POST `{baseUrl}/responses`）：

```json
{
  "model": "<transportModel 或 payload.model>",
  "input": [{ "role": "user", "content": [{ "type": "input_text", "text": "<prompt>" }, { "type": "input_image", "image_url": "data:image/png;base64,..." }] }],
  "tools": [{ "type": "image_generation", "model": "<image model>", "action": "edit", "input_image_mask": { "image_url": "data:image/png;base64,..." }, "size": "1536x864", "background": "transparent", "output_format": "png" }],
  "previous_response_id": "<可选：上一轮 response id>"
}
```

- 仅 `edit_image` 支持；`size/quality/background/output_format/output_compression` 按需传递（`auto` 不下发）；
- mask 只取第一张（与 Image API 语义一致）；
- 响应归一化：`output[].type === "image_generation_call"` 的 `result` → `data[].b64_json`（沿用现有图片结果渲染），`response_id` 随结果返回供下一轮串联；
- 无图片结果时失败关闭（`IMAGE_RESPONSES_RESULT_MISSING`）。

### 11.4 回归测试

- `test/unit/image-edit-responses-transport.test.js`：
  - 传输只对 `edit_image` 生效且默认为 `image_api`；
  - 请求包含 `image_generation` 工具、`action=edit`、`input_image_mask`、目标图 `input_image` 与参数透传；
  - `previous_response_id` 与 `transportModel` 正确转发；
  - 响应归一化为 Image API 形状并保留 `response_id`；
  - 无图片结果失败关闭；
  - job 目标 URL 按传输选择 `/responses` 或 `/images/edits`。

### 11.5 待实现（客户端串联）

- 编辑器/图片任务把 `transport` 与会话内 `previous_response_id` 传给服务端；
- 图片结果写入会话后记录 `response_id`，下一轮编辑自动带上；
- 设置页提供传输选择（默认跟随部署配置）。


## 视觉布局更新（2026-09-12）

编辑器采用桌面三栏工作台布局：

- 不显示顶部品牌栏或标题工具栏，编辑工作区直接铺满视口；
- 左侧“编辑工具”按顺序展示“标记评论 / 背景移除 / 画质提升 / 局部擦除 / 调整尺寸”，不提供快捷键徽标或快捷切换；标记评论复用点击后的十字准星光标图形，背景移除使用人物裁切图标，画质提升使用独立星芒图标，擦除工具的画笔大小和选填修改说明收纳在该栏底部；
- 桌面端左右面板高度跟随图片实际显示高度并在画布竖向居中，不再拉伸到整个视口高度；图片高度不足以容纳左侧工具时，左侧面板可在自身范围内滚动；底部操作栏紧贴图片组下方并随整体居中，不贴视口底部；窄屏纵向布局恢复各区域自然高度；
- 全屏图片预览中的“编辑”入口与消息图片上的编辑入口复用同一打开链路；每次显示预览时必须清除上次中断留下的 busy/disabled 状态，不能要求用户刷新页面；其他会话的任务状态不影响按钮点击，只有图片所属会话自身忙碌时提交阶段才给出可操作提示；
- 预览编辑打开流程同时处理 Promise 拒绝和同步异常，任何失败路径都必须恢复按钮并关闭预览，不能留下不可点击的半状态；
- 中间画布固定使用自动适应：按可用宽高与图片原始宽高的较小比例缩放，允许适度放大以尽量铺满，同时绝不拉伸或改变宽高比；画布不提供缩放、适应窗口、原始尺寸或全屏控件，默认不出现内部滚动；覆盖层保持归一化坐标；
- 右侧“操作历史”面板比左侧工具栏更宽（桌面默认 360px，按响应式档位降至 330/290px），与画布组成居中编辑组；画布列宽跟随实际图片显示宽度收缩，使两侧面板优先贴近图片，而不是固定贴住窗口边缘；
- 右侧面板只保留“操作历史”标题和数量胶囊，不再提供“全部”筛选、排序或图片属性页；记录按添加顺序展示评论、局部擦除、移除背景和画质提升；
- 同一会话的评论颜色从高对比专业色板中随机起点循环分配，画布编号标记与右侧评论序号使用同一颜色；评论和局部擦除记录在卡片右侧展示对应图片局部 PNG 截图，截图固定取图片短边 15% 的 4:3 小窗口，并以标记点或该次笔迹的中心为中心，不得随笔迹外接框放大取样区域；
- 底部工具栏宽度默认与左右工具栏和画布组成的整体编辑组一致；左侧显示图片尺寸、大小和格式，中部只保留撤销和重置，右侧提供按需显示的清空评论/选区、应用和取消；面板使用统一圆角、细边框、低对比阴影和卡片化评论列表，保持专业克制的视觉层级；
- “移除背景”和“画质提升”工具栏按钮支持点击选中、再次点击取消，右侧记录同时保留独立删除按钮；
- 编辑器仍以中立状态打开，不预选破坏性工具；评论、擦除可以多选累计，移除背景与画质提升各最多添加一次且移除背景不能与其他操作混合提交，提交仍复用同一个 edit_image 契约。
- 窄屏下三栏降级为工具栏、画布、操作历史面板的纵向排列，底部控制区允许换行。
