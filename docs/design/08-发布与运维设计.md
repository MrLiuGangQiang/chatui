# 08 发布与运维设计

## 1. 版本与发布准备

- `version.json` 是唯一版本来源；`npm run release:prepare` 自动递增并同步 npm 镜像、生成 `docs/releases/vX.Y.Z.md`。
- 发布说明必须在打 tag 的提交里，标题清晰、面向用户。
- `npm run check` 是发布门槛；本机有 Docker 时再跑 `npm run preview:release`，否则以 main CI 的 Exact Docker runtime 为准。

## 2. 发布流水线（不可妥协）

1. 干净候选基于当前 `origin/main`。
2. 推送 main 后等待必需 CI（含 Exact Docker runtime）成功。
3. 在该确切提交上打 **annotated** `vX.Y.Z` tag 并推送。
4. 流水线构建带 commit SHA 与 runtime source fingerprint 的候选镜像，按 digest 启动并验证 `/api/version`（版本、Git SHA、指纹三项一致）。
5. 同一 digest 提升到语义版本、`v` 前缀与 `latest` 标签；验证与提升之间禁止重建。
6. 发布（非草稿）GitHub Release，内容取自发布说明。
7. Docker Hub 与 ACR 版本标签必须解析到该 digest。

只有上述全部通过才可报告"发布完成"，否则明确说明"进行中"。热修复同样走完整流程。

## 3. 运行时身份

`server/build-identity.js` 计算 runtime source fingerprint；公告目录参与指纹，Release Notes 保持归档语义。浏览器用 `/api/version` 的 `sourceRevision` 与入口 `__CHATUI_ENTRY_IDENTITY` 做一致性检查，旧页面不在恢复会话/任务前继续执行。

## 4. 非功能性基线

| 项 | 基线/机制 |
| --- | --- |
| 首屏载荷 | 无构建 bundle；内容匹配 bundle immutable 长缓存，入口 always revalidate |
| 静态压缩 | 请求时 brotli/gzip + 内存缓存；支持 `.br/.gz` 旁挂预压缩 |
| 日志 | NDJSON，有界异步独立队列，按大小轮转，关闭时 flush |
| SSE | job/presence 长连接有 keepalive；服务关闭前统一结束 |
| 在线人数 | 30s 心跳、默认 120s TTL sweeper；单实例内存，配置 `REDIS_URL` 后共享 Redis 有序集合 |
| 任务 | TTL、最大任务数、驱逐时向订阅者推送终态 |

## 5. 运维与回滚

- 内容变更自动产生新 bundle 指纹，浏览器无须强刷即可拿到新版本；旧指纹不再下发 immutable。
- 回滚镜像即回滚行为；迁移类改动需先评审兼容与降级路径。
- `temp/` 仅存运行时日志与 pid，可安全清理；清理前先停止占用 8765 的 ChatUI 实例。
