# 12 多实例在线人数共享设计

## 1. 范围与原则

- 目标：`/api/presence` 返回"在线浏览器/设备数"：同一浏览器（同一 principal cookie）打开多个标签页只计 1；不同浏览器/设备各计 1。多实例部署时，任一实例的 join/leave/heartbeat 都能正确计入全局去重计数。
- 身份来源：`request-principal` 为每个浏览器签发的 HMAC principal cookie（HttpOnly、SameSite=Strict、默认 24h）。presence 不再以标签页 `clientId` 作为计数单位；`clientId` 只负责本机 SSE 连接生命周期与重连去重。
- 不做：不引入登录用户身份去重（同一设备的多个账号仍计 1）；不把 Redis 当成任务/会话存储；浏览器 presence 协议不变。
- 失败语义：Redis 不可达时 presence 端点返回 `503 {available:false}`，核心聊天/生图/附件不受影响；未配置 `REDIS_URL` 时保持单实例内存行为。
- 多实例前提：跨实例去重依赖所有实例共享相同的 `CHATUI_PRINCIPAL_SECRET`（与任务归属一致）；未配置时各实例各自随机生成 secret，同一浏览器在不同实例会被计为不同设备，需在部署文档中明确。

## 2. 流程/状态机

- `server/services/presence.service.js`：单实例内存实现。`Map<clientId, {res, lastSeen, principalKey}>`，`count()` = 去重后的在线 principalKey 数；未携带 principal 的连接回退按 clientId 计数（保证匿名/非浏览器客户端不丢计数）。
- `server/services/presence.redis.js`：配置 `REDIS_URL` 时启用。
  - 全局在线表为 Redis 有序集合 `chatui:presence:clients`，member = principalKey（owner key 的 base64url），score = lastSeen。
  - 每个进程本地保存 `Map<clientId, {res, principalKey, lastSeen}>`，只用于向本机 SSE 连接写数据与判断"本机是否还持有某 principal"。
  - join = 本地写入 + `ZADD`；touch = 刷新本地 lastSeen + `ZADD` 刷新共享 score；leave = 本地删除，若本机已无该 principal 的其它连接则 `ZREM`；sweep = `ZREMRANGEBYSCORE` 清理全局过期槽位 + 本地按 lastSeen 兜底清理本机假死连接。
  - 计数变化通过 Redis pub/sub 频道 `chatui:presence:events` 广播到所有实例。
- 有界陈旧性：跨实例同一 principal 的最后一个连接关闭时，若其它实例仍持有该 principal 的连接，其下一次心跳（默认 30s）会重新 `ZADD`，计数短暂回落随后恢复，误差有界且自愈，不作为回归门禁。

## 3. 契约与数据模型

- Redis key：`chatui:presence:clients`（ZSET，member=principalKey，score=lastSeen ms）。
- Redis channel：`chatui:presence:events`，消息体 `{count, timestamp}`。
- 浏览器/服务端 HTTP 契约不变：
  - `GET /api/presence` -> `{count, timestamp}`，count = 去重后的在线设备数
  - `GET /api/presence/stream?clientId=...` -> SSE presence 事件；路由从 `req.authPrincipal` 派生 principalKey 传给 join
  - `POST /api/presence/heartbeat` body `{clientId}` -> `{ok:true}`；路由从 `req.authPrincipal` 派生 principalKey 传给 touch
- 未携带 principal cookie 时（非浏览器客户端/测试直连），服务端回退按 clientId 计数，协议与既有单设备语义兼容。

## 4. API 与缓存语义

- presence 端点始终 `Cache-Control: no-store`。
- SSE 流响应经 principal cookie 注入路径（`decorateResponseForPrincipalCookie`）补发 Set-Cookie 与 `private, no-store`，首次访问的浏览器在开流时即获得身份。
- Redis 连接使用 `REDIS_URL`；密码只存在于服务端环境变量，不进入 `/api/config/public`、静态资源或日志。

## 5. 安全与可观测性

- `REDIS_URL`、`CHATUI_PRINCIPAL_SECRET` 不得出现在任何公开配置或静态目录。
- presence 身份来自 principal cookie；owner key 为 HMAC 派生值，仅以 base64url 形式作为 Redis member，不落日志、不作为用户身份对外暴露。
- Redis 连接错误记录到 `errorLog`，来源标记 `presence-redis` / `presence-redis-subscribe`。
- 日志遵守既有脱敏规则，不记录 Redis URL、密码或 principal 原始值。

## 6. 验收标准与回归测试

- 未配置 `REDIS_URL` 时，原 presence 行为与测试全部通过（同一 principal 多标签页计 1，不同 principal 各计 1）。
- 配置 `REDIS_URL` 时：
  - 两个不同 clientId、同一 principal join 后全局计数为 1。
  - 两个不同 principal join 后计数为 2。
  - 同一 clientId 重连不重复计数，principal 变更时不残留旧身份。
  - 心跳可在任意实例刷新共享 score（按 principalKey）。
  - sweeper 只清理过期全局槽位，本地按 lastSeen 兜底清理本机假死连接。
  - pub/sub 收到的 count 变化会写回所有本机 SSE 订阅者。
  - 路由对异步 snapshot/join/touch/leave 正确 await，并从 `req.authPrincipal` 派生 principalKey。
- 回归测试：
  - `test/unit/presence.service.test.js`（新增同 principal 多标签页去重、principal 变更、principal 派生）
  - `test/unit/presence-redis.service.test.js`（新增跨实例同 principal 去重、leave 按本地 refcount 收口、本地 TTL 兜底）
  - `test/unit/presence-routes.test.js`（新增路由从请求 principal 计数与心跳刷新）
  - 既有 `test/unit/presence-routes-async.test.js`、`test/unit/presence-ui.test.js` 保持通过。
