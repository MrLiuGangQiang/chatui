# 25 流式并发、会话隔离与任务续接设计

> 状态：已按“每会话独享一条 Chat Job 流”实现，待重新评审。此前共享 ids/shard/overflow polling 的 R1 方案及评审记录全部废弃；本版以最小帧和会话隔离为硬约束，必须与代码、测试、架构文档同次提交。

## 1. 范围、事实与决策

项目保持无构建、Node 原生 HTTP、现有 JobStore、principal cookie、Job DTO 和 image_batch_execution.v1。不改 CORS、身份认证、服务端 session epoch、持久化任务队列或任务 schema。

已确认问题与决策：

- 共享 `GET /api/chat-jobs/events?ids=...` 会让多个会话争用一条长连接，任务增多时互相阻塞；客户端改为每个会话对其当前 Job 建立独立 EventSource，服务端删除组订阅端点。
- 共享帧每帧重复 `id/status/error` 会显著增加字节数；compact chat 帧改为默认 SSE message，只发送最小增量或终态字段。
- 同 Job 多 waiter 独立累加会重复正文；服务端 Job aggregate 与浏览器 canonical aggregate 都必须只应用一次再分发。
- 旧 EventSource 迟到回调、旧 Job 对象、offset 回退和终态后的 running 回放必须被 epoch/对象引用/终态规则隔离。
- SSE 背压、keepalive、UTF-8 跨 chunk 和 batch 清理仍按既有质量门禁执行。

容量门禁分别验证 A=200 个独立 SSE response，每个 response 一个 Job；B=单个浏览器 runtime 内 200 个不同 session/Job 各自一条 EventSource；C=显式 MAX_UPSTREAM_CONCURRENCY=200 时 200 个受控上游任务。默认 30 active+100 queue 不擅自提高；测试不使用真实计费模型。

## 2. 客户端连接与聚合

`client/app/job-event-stream.js` 只保留会话流编排职责，`client/app/job-event-transport.js` 负责单连接传输，二者都不能依赖 UI。`client/core/job-event-aggregate.js` 是 compact 帧应用的唯一纯逻辑。

1. 一个 `sessionId` 同一时刻最多一条 Chat Job EventSource，URL 固定为 `/api/chat-jobs/:jobId/events?contentLength=<utf16>&reasoningLength=<utf16>`。任务 ID 只存在于 URL；不同 session 永不共用连接。
2. 同一 session/job 的多个 waiter 共享该连接和一份 canonical aggregate；后 waiter 立即收到已有状态。同一 session 不能同时拥有两个未终态 Job，冲突只拒绝后 waiter。末 waiter 退出后关闭本会话连接并删除 record。
3. compact chat 帧使用默认 SSE message：运行中只允许 `d`、`r`，首 Token 耗时只发一次 `ft`；终态只发 `done` 或 `e`，需要时在终态帧附带一次 `rt`；offset 越界才用 `z:1` 表示后用 `d/r` 重置。禁止每帧 `id/status/error`，禁止完整快照代替正常 suffix。
4. `d/r` 只应用一次再分发给 waiter；任意非终态 patch 保留既有正文、思考、metrics。终态优先，不能被之后的 running 回退。有 `z` 时先清空正文/思考再应用同一帧的 `d/r`。
5. 断线后先关闭旧 source 并推进 epoch，再用 canonical offset 建立唯一新连接。重试 1–5 秒、±20% jitter；连续失败 8 次停止本地 follower 但保留恢复 owner（非任务失败）。只有收到合法 Job 帧才清空失败计数，单纯 onopen 不清空。本设计不启用溢出 GET polling，也不允许 SSE 与轮询双写。
6. 所有 EventSource 回调和重连 timer 必须匹配 epoch；旧 source、旧 Job 对象和迟到 JSON 解析失败不得写入新 aggregate。pageUnload 停止重连并拒绝 waiter；closed manager 的 subscribe 立即拒绝。
7. offset 以 JS UTF-16 code unit 计量，正文/思考独立。缺 offset 默认 0；非法数字拒绝。offset 越过服务端内容长度时服务端发一次 `z` 加当前完整正文/思考；终态最后 suffix 必须先交付再结算。

## 3. 服务端事件、背压与回放

在 `server/jobs/events.js` 统一组织单 Job 绑定、公开视图和最小帧；通用分块 writer 继续位于 `server/http/sse-writer.js`。

- 每条 response 只绑定 URL 中一个 Job，按 JobStore 对象引用 + principal 匹配；旧对象 notify 查到替换对象时直接忽略，不能误删新 binding。dispose、终态和 response close 统一摘除 binding，末 binding 结束 writer；shutdown 去重清理 subscriber。
- `compactJobFrame` 是 compact 正文/思考/首 Token/终态/重置编码的唯一实现；`publicJob` 的 GET 快照和 SSE binding 都必须复用它，禁止复制 status/id 序列化。
- 每个 binding 的 offset 以被 writer 接纳的帧为准，从权威 `job.data` 切 suffix，不依赖可能过期或丢失的 `streamDelta`。运行中按 25ms 合并 dirty Job，不排队每 token；初始回放和 terminal 立即 pump，每次最多 16 帧后 setImmediate 让出事件循环。
- compact 每帧正文与 reasoning 合计最多 8192 UTF-16 单元；长回放分多帧，终态只在该 binding 的 suffix 全部接纳后发送。非 compact image/batch Job 保留现有完整 DTO 与 `event: update`，不改变图片/批次 data。
- writer 一次只持有一帧，串行按块写入；write(false) 进入 BLOCKED 并等待 drain，不重写已接纳块。10 秒无 drain 只 destroy 该 subscriber 并摘除 binding，不暂停其他 subscriber 或上游 Job。keepalive 固定 15 秒注释帧且 unref；X-Accel-Buffering、no-store/no-transform、异常/关闭/超时清理保持既有契约。
- 删除 `GET /api/chat-jobs/events?ids=...` 组端点及 `ids/offset` 组校验；不存在或非 owner 的 `/:id/events` 仍返回同形流错误，不泄露任务存在性。

## 4. 上游完整性与资源边界

- 托管 chat runner 用 StringDecoder 贯穿上游 body 与 end；parser 对同一 chunk 的 streamDelta 先完成再 notify。25ms 输出合并不改变 Job 权威文本。
- 直通 proxy 下游写阻塞时停止读取上游并等待 drain，10 秒 abort 上游；managed proxy 下游慢或断线只断开该消费者，继续权威 Job 并可恢复，不把页面断线当用户取消。
- 不把“任意附件、无限输出”当作容量承诺。正文+思考合计默认 8MiB/Job，未终止 SSE event buffer 默认 1MiB，超限明确 Job error。完整输出和 terminal 计入 JobStore；默认 200 个 Job，部署 200 active 时另留排队与终态容量，不能驱逐正在服务的老任务。
- 不引入全局精确 RSS reservation。压力测试必须明确小文本负载、RSS/heap/event-loop 环境和结果；大附件继续受 10MiB 文件策略和请求 body 硬上限约束。

## 5. 会话隔离与批量删除

安全边界是 principal，不是前端 sessionId。本地工作流固定捕获 sessionId、Job id、liveItem/displayItemId/responseIndex、run 对象；后台回调写目标 session。流式 DOM 写入必须同时校验 activeSessionId 和精确节点所有权，禁止用 responseIndex 回退，后台 session 不得写当前 DOM。display item 的 outputStarted 必须先在 canonical display 更新，重复快照、checkpoint、节点复用不得残留过期状态。

session 资源清理复用 submit-workflow.helpers 的 batch index/child key 读取。删除 session 时枚举并清理本 session child 前缀、父 Job、恢复缓存和媒体引用；父 dispose 级联 child。旧 child 迟到更新必须比较父对象引用，不能污染新 parent；其他 session 资源前缀不动。

## 6. 实施与测试门

实现文件：client/app/job-event-stream.js、job-event-transport.js、job-event-aggregate.js、job-workflow.js、job-resume-workflow.js、client/services/job-service.js；server/jobs/events.js、http-contract.js、chat-image.js、server/api/routes/jobs.js、server/api/router.js、server/app.js。不得新增共享 chat Job 组订阅入口。

每个根因独立红绿测试，通过自定义 runner 自动发现并进入 `npm run check`/CI。`npm run test:streaming` 只提供同一 runner 的聚焦别名。

- **Profile A（服务端连接）**：`test/smoke/chat-job-sse-capacity.test.js` 建立 200 个独立 SSE response，每个绑定一个 Job；每个 Job 发送正文/思考增量、终态和 keepalive/背压验证。全部 terminal、无丢失/重复/pending，测试末 subscriber/timer 清零。
- **Profile B（浏览器会话隔离）**：`test/unit/chat-job-event-stream*.test.js` 恢复 200 个不同 session/Job，必须产生 200 条不同 URL 的 EventSource；同 session/job waiter 共享，不同 session 不共享，切换/断线只重连所属连接，最终 aggregate 逐 Job 相等且 0 跨会话写入。
- **Profile C（上游准入）**：ConcurrencyLimiter fixture 验证默认 30 active/100 queue 和显式 200 active 的准入/释放，不调用供应商。
- **服务器/协议门**：`test/unit/server-job-event-stream.test.js`、`server-job-event-backpressure.test.js`、`job-event-payload.test.js` 覆盖最小帧无 `id/status/error`、默认 message、UTF-16 suffix、`z` 重置、终态 `done/e/rt`、stale object、drain、keepalive 和单连接关闭。
- **客户端门**：覆盖标题中的 `d/r` 一次应用、same session/job 连接复用、session conflict、offset 重连、pageUnload 和旧回调隔离。
- **运行残留门**：所有 profile 结束时 EventSource、subscriber、timer、record 为 0；测试端口 8765，占用时复用或报告，不换端口。
